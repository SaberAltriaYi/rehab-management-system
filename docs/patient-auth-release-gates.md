# 患者强身份与发布门禁（更新于 2026-10-26）

> 状态：**未开放**。本文件是实现与验收约束，不是已完成认证的证明。

## 当前实现与仍然关闭的发布入口

- 旧 `/app-api/app-patient/auth/login` 和服务层旧 `login` 继续拒绝手机号＋患者编号登录。手机号、患者编号及固定算法生成的用户 ID **不得**作为身份凭据。
- 现有 `/app-api/app-patient/auth/bind` 已接入已认证 MEMBER 身份＋一次性机构邀请；这不是匿名接口。邀请密钥未配置时失败关闭。兑换必须核对会员域 API 返回的当前启用账号、手机号、档案手机号及患者编号（若提供）。只支持 `self`，客户端声明 `caregiver/imported` 不构成授权。
- 已有邀请表、租户作用域摘要及唯一索引；兑换使用精确摘要行锁、事务和单次状态更新，不再锁机构内所有待用邀请。并发绑定的唯一键冲突转为业务拒绝，事务回滚；软删除、撤销、过期、跨机构与已使用邀请不能兑换。数据库迁移账本保持原样，本批没有新增或重写迁移。
- 患者读写入口仍要求 MEMBER 和有效绑定；入口检查当前会员未禁用、会员/绑定/患者手机号一致。换号、停用和解绑不能继续凭旧绑定访问。旧令牌批量撤销、绑定来源治理和异常风险撤销仍需单独验收，不能把这些检查当成全部令牌治理已经完成。
- Core UniApp 的患者 UI 开关默认 `false`；可供隔离验收，不代表批准面向真实患者启用。首次短信登录后兑换邀请，已绑定者以后短信登录并校验现行绑定，不重用已消费邀请。患者访问令牌只在页面/进程内存保存，不保存刷新令牌；旧持久化患者会话一律清除，刷新/重启需再登录。员工存储策略本批不改，仍需平台安全存储验收。
- 正常退出尝试调用对应身份的服务端注销，并始终清除本机凭据；网络失败会告知服务端注销未确认。HTTP 401 和业务 401 都清除客户端会话。不能将本机清除等同于离线情况下已成功撤销服务端令牌。
- 本批测试使用随机内存数据库和模拟域适配器，不连接现用业务库。H2 锁/回滚测试不代替真实 MySQL、短信、网关和浏览器端到端验收。独立 HEP 患者壳的旧持久化交接仍是后续待修项，不能用 Core 移动端修复宣称 HEP 全部通过。

### 当前未关闭的风险

真实短信提供方及多维限频/防枚举、同源 H5 会话安全评审、监护人独立授权、邀请并发发放/撤销审计及上限策略、历史绑定/令牌处置、HEP 患者身份交接和微信/App 真机仍需完成。当前邀请默认 30 分钟，历史实现允许最长 7 天，与下述建议不超过 24 小时的发布策略尚有差异，应在后续工作包中统一并回归。

## 目标流程：机构线下核验＋短期单次邀请＋已核验手机验证码

1. **机构发放**：仅具备专属授权的员工，在正确租户、患者档案及线下核验记录的上下文中发起邀请；记录最少量审计信息和撤销理由。`patient_no`、手机号、患者 ID 或它们的可预测组合不得成为邀请凭据。护理人／代办人的授权需独立设计、取得同意，不能直接复用患者邀请。
2. **短期邀请**：使用密码学安全随机源生成至少 128 位不可预测值；服务端仅存储带独立密钥的摘要（例如 HMAC-SHA-256），记录租户、患者、已登记手机号的受控引用、发放人、状态与过期时间（建议不超过 24 小时）。邀请码仅通过经批准的渠道发给已线下核验对象，不出现在 URL 查询参数、分析埋点或应用日志；支持撤销、过期和原子单次消费。
3. **独立手机号证明**：仅向已核验并获同意的档案手机号发送一次性验证码。需对接获批准的短信服务商，并校验送达、失败与退订治理。验证码限时（建议不超过 5 分钟）、限次，服务端不存明文、不在日志回显；对租户、联系方式、设备和网络来源分别设定服务端限频及风控。客户端 CAPTCHA 不能代替服务端限频。
4. **防枚举与绑定**：邀请不存在、过期、已使用、手机号或验证码不匹配时对外统一错误语义，不透露档案或手机号是否存在；核验成功后在单个事务中消费邀请并创建／更新正确租户的绑定，防重复提交及并发双花。患者账号必须来自受控身份体系，不得再用 `90_000_000 + patientId` 计算。
5. **令牌与会话**：仅在双重证明及租户／主体校验全部通过后签发明确患者作用域的短期令牌；刷新令牌轮换并支持撤销。失效条件至少包含解绑、换绑手机号、身份核验撤销和异常风险事件；上线前处理所有旧版患者令牌。H5 优先评估同源 HttpOnly/Secure/SameSite 会话，原生端使用 Keychain／Keystore，微信小程序须有经评审的最小化凭据和到期策略；通用 `uni.setStorageSync` **不能**作为患者刷新令牌的发布方案。

## 必须通过的隔离验收

- 非法、过期、已使用、并发消费的邀请；错误／重放验证码；号码不一致；同租户不同患者与跨租户调用；无授权员工发放、护理人越权；旧令牌访问所有患者读写接口；日志脱敏。
- 服务端多维限频与防枚举（含来源地址只能采信受信代理头）、验证码提供方故障、密钥轮换、撤销与刷新令牌重放；启动后及关闭 CAPTCHA 的测试不得冒充开启 CAPTCHA 的生产验收。
- 使用随机 Docker 项目／卷和合成患者完成代理→Java→MySQL／Redis 的正反链路，补齐手机端安全存储、微信真机、备份／恢复及发布前安全评审。

**不得仅因完成构建、设置前端开关或添加一个后端配置项就批准真实患者使用。** 当前没有真实短信、完整患者浏览器路径和平台安全存储验收证据。工程实现、合成测试、运行启用和发布批准必须分别记录。
