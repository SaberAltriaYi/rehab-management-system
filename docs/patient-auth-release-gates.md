# 患者强身份与发布门禁（2026-09-26）

> 状态：**未开放**。本文件是实现与验收约束，不是已完成认证的证明。

## 当前闭锁

- `/app-api/app-patient/auth/login` 与 `/auth/bind` 返回 HTTP 403；服务层的旧 `login`、`bindPatient` 也在查档案／签发令牌／写入绑定前拒绝。手机号、患者编号及固定算法生成的用户 ID **不得**再作为身份凭据。
- `/app-api/app-patient` 下的其余读取与写入接口也暂时拒绝，即使请求携带旧版曾签发的令牌，也不能以原有绑定记录绕过新身份核验。当前未实施服务端旧令牌批量撤销；上线前须明确撤销与失效策略。
- UniApp 患者登录不能用环境变量启用，不再展示手机号／患者编号表单，也不会请求旧接口或持久化患者令牌；读取旧版患者会话时清除本地记录。员工登录路径暂不改变。
- 未连接既有患者库，不迁移／修改真实业务卷。任何后续功能开发和测试使用随机隔离环境及脱敏数据。
- 已提供未接入路由的 `PatientInvitationTokens` 原语及合成数据单测：生成 256 位随机短码，并对租户作用域使用独立外部密钥计算 HMAC 摘要；**仅证明生成、域隔离与摘要校验**。没有邀请记录表、授权发放、过期／单次原子消费、短信核验或真实令牌会话，不得据此开放入口。

## 目标流程：机构线下核验＋短期单次邀请＋已核验手机验证码

1. **机构发放**：仅具备专属授权的员工，在正确租户、患者档案及线下核验记录的上下文中发起邀请；记录最少量审计信息和撤销理由。`patient_no`、手机号、患者 ID 或它们的可预测组合不得成为邀请凭据。护理人／代办人的授权需独立设计、取得同意，不能直接复用患者邀请。
2. **短期邀请**：使用密码学安全随机源生成至少 128 位不可预测值；服务端仅存储带独立密钥的摘要（例如 HMAC-SHA-256），记录租户、患者、已登记手机号的受控引用、发放人、状态与过期时间（建议不超过 24 小时）。邀请码仅通过经批准的渠道发给已线下核验对象，不出现在 URL 查询参数、分析埋点或应用日志；支持撤销、过期和原子单次消费。
3. **独立手机号证明**：仅向已核验并获同意的档案手机号发送一次性验证码。需对接获批准的短信服务商，并校验送达、失败与退订治理。验证码限时（建议不超过 5 分钟）、限次，服务端不存明文、不在日志回显；对租户、联系方式、设备和网络来源分别设定服务端限频及风控。客户端 CAPTCHA 不能代替服务端限频。
4. **防枚举与绑定**：邀请不存在、过期、已使用、手机号或验证码不匹配时对外统一错误语义，不透露档案或手机号是否存在；核验成功后在单个事务中消费邀请并创建／更新正确租户的绑定，防重复提交及并发双花。患者账号必须来自受控身份体系，不得再用 `90_000_000 + patientId` 计算。
5. **令牌与会话**：仅在双重证明及租户／主体校验全部通过后签发明确患者作用域的短期令牌；刷新令牌轮换并支持撤销。失效条件至少包含解绑、换绑手机号、身份核验撤销和异常风险事件；上线前处理所有旧版患者令牌。H5 优先评估同源 HttpOnly/Secure/SameSite 会话，原生端使用 Keychain／Keystore，微信小程序须有经评审的最小化凭据和到期策略；通用 `uni.setStorageSync` **不能**作为患者刷新令牌的发布方案。

## 必须通过的隔离验收

- 非法、过期、已使用、并发消费的邀请；错误／重放验证码；号码不一致；同租户不同患者与跨租户调用；无授权员工发放、护理人越权；旧令牌访问所有患者读写接口；日志脱敏。
- 服务端多维限频与防枚举（含来源地址只能采信受信代理头）、验证码提供方故障、密钥轮换、撤销与刷新令牌重放；启动后及关闭 CAPTCHA 的测试不得冒充开启 CAPTCHA 的生产验收。
- 使用随机 Docker 项目／卷和合成患者完成代理→Java→MySQL／Redis 的正反链路，补齐手机端安全存储、微信真机、备份／恢复及发布前安全评审。

**不得仅因完成构建、设置前端开关或添加一个后端配置项就移除闭锁。** 目前没有短信服务商及真机安全存储的验收证据；强身份流程仍属待实现项。
