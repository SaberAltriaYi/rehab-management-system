# 患者端微信首发：开放前核验与实施状态

记录日期：2026-09-27。目标工作树：`rehab-module-enable-clean`，检查时 HEAD 为 `49b3e40`。本记录补充 [患者强身份与发布门禁](patient-auth-release-gates.md) 和 [跨平台发布计划](mcp-cross-platform-installer-release-plan-2026-09-26.md)，不是生产发布批准。

## 本轮确认的目标与实际边界

- 用户希望首批通过**微信小程序**向真实患者开放，并选择「机构核验＋邀请＋短信验证码」为目标身份方案；用户表示将提供生产环境信息。目前尚未收到生产环境地址、负责人、备份/恢复证据、短信服务商接入资料或微信 AppID 等实际资料。
- 当前 `/app-patient/auth/login`、`/auth/bind` 及患者资料接口仍闭锁；控制器与服务端旧登录/绑定均拒绝。现有请求体的手机号、患者编号不是身份凭据，不得通过配置或前端开关恢复旧路径。`PatientInvitationTokens` 只有离线生成、租户作用域摘要和合成测试；尚无邀请记录、原子消费或短信验证服务。
- 已确认的 `172.16.8.41:8443` 是项目文档中的**测试**地址，不能作为生产患者接入目标；不接触现有患者数据库和业务卷，不部署、不推送，不向患者发送邀请或验证码。

## 最小实施顺序（每项独立验收，不得跳级）

1. **环境与责任人**：取得生产环境的明确标识、合法 HTTPS 域名/网络拓扑、数据负责人、发布审批和应急联系人；先在隔离预生产完成数据库与附件一致备份、恢复、停用/撤销演练。不要在测试域名或真实卷上试错。
2. **机构发放**：为授权员工在同租户、已线下核验的患者上下文中创建短期单次邀请；只保存带独立密钥的摘要及最少量审计信息；支持过期、撤销、原子消费和并发防重，禁止使用手机号/患者编号/可预测 ID 当邀请密钥。护理人授权另行处理。
3. **独立手机证明**：对接经批准的短信服务商及已核验手机号；验证码限时、限次、不留明文；服务端按租户、手机号、设备、可信代理来源限频；统一错误语义防枚举，并覆盖供应商故障与重放。
4. **患者会话与权限**：双重证明和租户/主体校验成功后才签发患者作用域会话；实现撤销、刷新轮换、旧令牌失效、解绑与风险事件失效；按患者范围在全部读写接口服务端验证，不仅依赖 UI。评审微信小程序安全存储及到期策略，通用 `uni.setStorageSync` 不作为刷新令牌正式方案。
5. **微信发布验收**：提供机构所有的 AppID、合法 request HTTPS 域名、隐私/平台资料和真机；隔离环境验证邀请/短信/令牌/租户/越权/日志脱敏/异常与恢复，再完成微信开发者工具、体验版、真机、平台审核和安全评审。最后由业务/安全/运维责任人签署生产切换和回退方案。

## 当前判定与下一批

**患者真实环境开放：阻断。** 缺少可运行的邀请＋短信双重证明、患者令牌安全策略和微信/生产验收证据；本轮保持后端拒绝门禁与客户端关闭。后续先取得实际生产/短信/微信资源，再在隔离库完成邀请发放、消费和审计的数据契约与迁移测试；其中任何单项完成都不等于可以去掉闭锁。管理端 `pnpm ts:check` 独立于患者认证，仍须按模块取得本轮新诊断与逐批归零证据，不以旧日志当作当前通过。
