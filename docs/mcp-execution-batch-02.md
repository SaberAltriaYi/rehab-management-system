## 2. 真实基线发现

### 2.1 “保存草稿”会被标记为已完成（已修复并在补丁部署中复测）

真实浏览器中为上述合成患者新建未填写 Top Tier 的 SFMA，点击“保存草稿”。旧部署接口返回成功，评估 ID 为 `20023`；回到列表后状态为 `completed`，而不是 `draft`。这会把可恢复的临床录入误表示为完成。

修复包括：

- 草稿提交的模块状态写为 `partial`；
- 服务端在创建/更新请求显式要求 `status=draft` 时保留父评估草稿状态；
- 空主模块的初始化状态改为 `not_started`，避免空数据被认作完成；
- 模块数据保存接口增加可选 `keepAssessmentDraft`，供后续分段保存/自动保存显式维持草稿，而不是由单个已完成模块意外触发临床完成。

### 2.2 完整性校验与草稿语义混用（已修复并在补丁部署中复测）

`综合评估`表单在未选择模块时返回完整性校验失败。旧创建页对“保存草稿”和“保存并继续/返回”调用同一动态表单校验，导致未完成内容无法按草稿语义保存。

修复后：基础结构（患者、Episode、类型、日期）仍必须有效；只有非草稿操作执行动态表单的完整性校验。草稿仍保存为 `partial`，不会绕过任何完成操作的校验。

### 2.3 已有评估可以在前端尝试更换患者（已修复并在补丁部署中复测）

服务端已拒绝历史评估换人，但旧编辑页仍允许操作患者选择器，造成无效操作和混淆。编辑模式现在禁用患者选择器；Episode 仍可在同一患者内按服务端规则调整。

## 3. 防丢失与并发交互加固

创建/编辑页补充了以下前端保护：

- 防止保存请求尚未开始时的重复点击；保存过程中表单禁用；
- 请求前复制基础字段和模块数据；保存期间同时禁用表单并覆盖加载层，因此成功响应后可安全记录当前规范化表单状态；
- 仅当仍在同一路由时更新“已保存快照”或跳转；
- 路由离开前对未保存修改进行确认，保存进行中拒绝离开。

另修复编辑加载时的异步竞争：加载历史评估期间暂时抑制“患者变更→清空 Episode”观察器，并以请求序号丢弃过期 Episode 响应。否则重置/编辑页可能在加载完成后错误地表现为“有未保存修改”。

这些改动不改变评估原始数据结构，不引入数据库迁移，也不启用 AI。
