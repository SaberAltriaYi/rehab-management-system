# S1 工作包及退出条件

以下是下一阶段任务，不因 S0 文档完成而自动执行部署、身份变更或临床签发。优先修复现有实现，不换数据库/框架，不增加大型产品。

| ID/优先级 | 工作包/角色 | 依赖 | 可验证交付/退出条件 |
| --- | --- | --- | --- |
| S1-01 P0 | 身份与测试部署；技术/QA | 测试策略、用户跳过账号决定 | 无需真实资料的测试环境可重建；获授权身份具最小权限；缺身份时明确 BLOCKED，不注入 Token |
| S1-02 P0 | 患者正常登录/绑定及 HEP 交接；后端/前端/安全 | S1-01，现有会员/邀请代码 | 登录、退出、过期、解绑、重放/并发、错误患者/机构/监护人正反用例；真实短信/平台配置未就绪不开放真实患者 |
| S1-03 P0 | 合成数据标记和统计策略；Core/QA | S1-01 | 新老测试记录有受控来源标识、排除与归档机制；不能靠姓名模糊匹配批量删除；真实计数不变 |

| S1-05 P0 | Core→运动工作区→复核→收件箱；双服务/QA | S1-01/04、单次票据/修订契约 | 真实HTTP和浏览器正向、过期/重放/机构患者错配、变更后旧快照拒绝、幂等；未经确认的视频同步不升级为已确认 |

| S1-07 P1 | 可靠同步与对账；后端/运维 | S1-05/06、现有inbox/outbox | 故障/恢复、超时重试、幂等、积压和人工补偿均可见；不自动覆盖另一系统主档或跨库直写 |
| S1-08 P1 | 内容/报告契约；临床/后端 | 范围与版本冻结 | 首批高频动作内容、剂量/侧别/版权/审核；原始数值/单位/图帧/来源与报告版本一致，无数据不补造 |
| S1-09 P1 | UI任务流基线；前端/QA/治疗师 | 角色/患者疗程关系、访谈模板 | 角色首页和患者工作区流程稿；保存/加载/失败/无权规范、390px/平板任务；S2才扩大视觉改版 |
| S1-10 P1 | 联合制品与迁移/恢复门槛；DevOps | 源码/版本/开关矩阵 | 不可变版本和摘要、三服务健康、私有配置、备份恢复；Rust/Win/Mac和真实设备缺口不得填PASS |
| S1-11 P1 | CRM候选与会员边界；Core/QA | S1-04、部门/权益规则 | CRM单独候选，双部门浏览器/导出/统计拒绝；会员过期只限制新执行不隐藏历史风险；默认不部署未验收候选 |

## S1 实施顺序

先 S1-01/02/03 → S1-04 → S1-05/06 → S1-07；S1-08/09/10 可在对应依赖满足后交叉，S1-11 不阻塞已满足门槛的纯康复内部版。若患者身份暂缺，可继续合成隔离接口与UI任务设计，但不能把患者正向流程标记通过。

## 验收记录要求

每一用例保留构建/提交、环境、输入来源/版本、角色、前提、实际操作、期望/实际、匿名证据位置、失败/跳过原因及回归结果。PASS、FAIL、BLOCKED、NOT_RUN和不适用分开。

必要验收：患者/治疗师/机构管理员分别验证；对象/机构/部门隔离；草稿/复核/签发/旧版本；无权限、重复、过期、超时、弱网与恢复；备份和升级不损坏原有数据。合成临床判断必须标记仅测试，不形成真实患者治疗建议。

不能以完成 S0、增加菜单、编译成功、接口健康或历史测试计数代替 S1 退出。下一阶段开始前记录获准的测试身份路径及候选发布范围，仍维持 AI 关闭。
