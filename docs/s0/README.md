只读工具：`script/rehab/s0_inventory.py`。Python 3.11+，不需要 Docker/MySQL、不登录系统，不读取 `.env`。默认不访问网络，`--probe` 仅允许固定的未登录回环状态检查，不跟随重定向、不继承代理、不关闭 TLS 校验。工具不验证所有者 MFA 或临床业务。

```bash
python3 -B script/rehab/s0_inventory.py
python3 -B script/rehab/s0_inventory.py --probe
python3 -B -m unittest discover -s script/rehab -p 'test_s0_inventory.py' -v
```

冻结快照记录的是 **S0 实施输入基线**，不是包含它自身的最终提交 SHA，避免自引用。S0 交付提交通过 Git 记录；进入 S1 后重新生成新的、带日期的快照，不覆盖本次证据。生成工具测试通过不能等同全部产品测试通过。

## S0 退出条件

- [x] 一套工作室产品、三个业务工作区和独立 Owner 边界已书面确定。
- [x] 首版包含/不包含、角色、主数据、演练与运行边界已确定。
- [x] 关键源码和已知工作树已登记；存在差异的同名引擎保留，不误删。
- [x] 分支、版本、固定制品、开关与已知发布阻塞已登记。
- [x] 竞品统一案例、计时方式、失败/数据迁出/接口授权记录方法就绪。
- [x] 测试身份策略及未完成状态明确，不冒充完成治疗师/患者正向验收。
- [x] S1 任务顺序、依赖与可测试退出条件就绪。
- [ ] 治疗师访谈、竞品登录/付费演示、临床协议确认尚未执行；这是后续验证，不填虚假结果。

**完成口径：S0 的工程盘点、范围和验收准备包已交付；真实竞品体验、用户访谈、临床有效性和上线审批不属于已完成事项。** 人员可以在 S1 开始时修订产品假设，但须记录决策和影响，不默默增加首版范围。
