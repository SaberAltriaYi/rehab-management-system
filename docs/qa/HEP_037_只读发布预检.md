# HEP 037 只读发布预检

本工具用于在正式内部版升级前拒绝明显不一致的部署状态。**预检通过不是临床上线批准**；只检查候选完整性、已报告的部署状态、Core/HEP 目标与当前本机严格 TLS 连通性。它不迁移数据库、不重启服务、不启用桥接、不配置或读取密钥、不操作 macOS 钥匙串。

## 使用

优先使用 `--live` 直接读取当前安装版的只读数据库状态、运行资源版本、Docker 环境中的指定桥接字段与本地 HEP 配置；机器令牌只在进程内进行等值核对，不写入输出。**以下示例按当前不就绪状态应返回退出码 `2`**：

```bash
node desktop/scripts/hep-release-preflight.mjs \
  --candidate '/Users/saber/my-project/rehab-runtime/validation-evidence/qa-20261111-committed-release-candidate/1.0.0' \
  --live
```

成功的技术预检需要候选运行资源哈希校验通过且包含 037、已安装版本和数据库版本一致并包含 037、HEP 表/菜单就绪、桥接已启用、机器令牌与 JWT issuer/JWKS 一致、Core 私钥在容器内可读、HEP Core 目标与当前回环 HTTPS 18443 完全一致、严格 HTTPS `/login` 返回 200。`--live` 只能在使用既定项目名称和本机配置目录的 Mac 上取得这些证据，无法连接时必须报告阻断，不能冒充通过。

旧版手工参数仍可用于模拟场景，但命令行结果会固定附加 `MANUAL_EVIDENCE_UNVERIFIED` 阻断，**不能靠手工填写成功值批准部署**。

退出码：`0` 表示本机观测到的技术前置条件符合且 Node 默认严格 TLS 探测通过；`2` 表示阻断。即使返回 `0`，仍需要独立验证 Chrome/Safari/curl 系统信任、真实 OAuth2/JWT 跨租户绑定、受控可恢复备份、正常账号及人工临床审核，才能进入下一阶段审批。

### 安全限制

- 仅向本机 `127.0.0.1`/`localhost` 发起未经认证的 HTTPS 连通探测；拒绝外网探测，不使用 `curl -k` 或关闭证书校验。
- 不把 `.env`、私钥、Token、患者资料或完整进程环境写入命令和日志。
- 绝不对现用 036 数据库直接运行 037；升级前必须在受控备份副本完成演练并取得正式授权。
- HEP 服务的 JWKS/issuer、短期 JWT 及事件回传完整一致性必须另做 E2E，不能仅凭这个静态预检证明。
