# HEP 037 只读发布预检

本工具用于在正式内部版升级前拒绝明显不一致的部署状态。**预检通过不是临床上线批准**；只检查候选完整性、已报告的部署状态、Core/HEP 目标与当前本机严格 TLS 连通性。它不迁移数据库、不重启服务、不启用桥接、不配置或读取密钥、不操作 macOS 钥匙串。

## 使用

先从当前安装版的只读 SQL/运行配置独立核实迁移版本（`internal_schema_history`）、HEP 桥接实际开关和 HEP 服务真正使用的 Core URL，然后填入参数。例如下例**代表当前已知不就绪状态**，故应返回退出码 `2`：

```bash
node desktop/scripts/hep-release-preflight.mjs \
  --candidate '/Users/saber/my-project/rehab-runtime/validation-evidence/qa-20261111-committed-release-candidate/1.0.0' \
  --deployed-ledger 001-036 \
  --bridge-enabled false \
  --hep-core-url http://127.0.0.1:48080
```

成功的技术预检需要候选运行资源哈希校验通过且包含 037、已部署版本包含 037、桥接实际启用、HEP Core 目标与当前回环 HTTPS 18443 完全一致、系统默认信任的严格 HTTPS `/login` 返回 200。工具只读取候选版本文件并检查运行时哈希；`--deployed-ledger`、`--bridge-enabled` 和 `--hep-core-url` **属于操作者输入，并非工具已独立证实的运行状态**。因此，输入本身必须附带脱敏现场证据，不得人为输入预期成功值来绕过门禁。

退出码：`0` 表示已提供的技术前置条件全部符合且本机严格 TLS 探测通过；`2` 表示阻断。即使返回 `0`，仍需要确认机器签名/JWKS/issuer/租户绑定、受控可恢复备份、正常账号及人工临床审核，才能继续下一阶段审批。

### 安全限制

- 仅向本机 `127.0.0.1`/`localhost` 发起未经认证的 HTTPS 连通探测；拒绝外网探测，不使用 `curl -k` 或关闭证书校验。
- 不把 `.env`、私钥、Token、患者资料或完整进程环境写入命令和日志。
- 绝不对现用 036 数据库直接运行 037；升级前必须在受控备份副本完成演练并取得正式授权。
- HEP 服务的 JWKS/issuer、短期 JWT 及事件回传完整一致性必须另做 E2E，不能仅凭这个静态预检证明。
