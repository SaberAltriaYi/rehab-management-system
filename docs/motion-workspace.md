# 原生运动评估工作区：安装、权限及完整流程

主系统负责机构、患者、康复周期、治疗师及评估归属；独立工作区负责运动学文件读取、原生模型和证据复核。不是重新建立一个患者库，也不把模型统计自动当成 FMS/NASM-CES/SFMA 评分。此功能没有云端 AI 或自动视频上传。

## 部署前置

1. 主系统沿用 MySQL/Redis 及原部署。独立 Python 服务部署项目为 `rehab/services/rehab-reporter`，使用自身私有运行目录，不接管主数据库。安装其 `requirements.txt`、`requirements-motion.txt` 并构建 `desktop-motion-ui`；OpenSim 4.6/Python 3.13 的平台要求见该项目说明。视频取帧另需本机 ffmpeg/ffprobe。
2. **先备份并在隔离副本验证**，执行 `deploy/internal/migrate.sh verify-files`、`status`、`apply`，确认 032/033 实际登记。不要直接对业务库执行零散 SQL，也不要重跑新安装器。032 新建结果收件箱和两项权限；不改患者列和原评分。033 保持 AI 训练草稿关闭。
3. 两边安全运行环境配置同一个 `REHAB_CORE_BRIDGE_TOKEN`，至少 32 个随机字符。不可写到代码、Git、浏览器或聊天；建议从受限配置文件/服务管理器注入，不在公开终端打印。
4. Core 配置 `REHAB_ASSESSMENT_SERVICE_URL`（Java 服务能够访问的工作区地址）和 `REHAB_ASSESSMENT_PUBLIC_URL`（治疗师浏览器能够访问的工作区根地址）。两者可不同。**手机上的 127.0.0.1 指手机本身**，局域网部署不能用它冒充服务器。Docker 容器内的 localhost 也不指宿主机。
5. 默认未配置连接时关闭。非本机 URL 必须 HTTPS；内部 CA 要分别加入浏览器和 Java 信任库，禁止忽略证书校验。独立服务沿用明确私有 IP + TLS 启动规则，不绑定全部地址。服务端拒绝重定向，不向任意用户输入 URL 发送服务凭证。独立站点应使用自己的根地址，不用未经配置的子路径代理。
6. Core 重新构建后端及 `pnpm build:internal`，再按原流程更新服务；不要把代码编译通过当作现有容器已升级。独立工作区启动时执行自己的带固定校验和增量迁移。无需为 Core 模式创建默认/共享工作区账号。

## 权限配置

系统管理 → 角色管理 → 菜单权限，给指定临床成员分配：

- `rehab:motion:query`：主系统动作评估查看。
- `rehab:motion:workspace`：进入独立运动学工作区及查看接收历史。
- `rehab:motion:create` + `rehab:motion:upload`：工作区编辑/导入。
- `rehab:motion:review`：结构化结果审核、临床可用性及同步确认、主系统结果复核。
- `rehab:motion:sync`：提交及接收结果快照。
- `rehab:motion:sign`：工作区负责人签发（仍需原有治疗师复核前置条件）。

新权限不批量授给所有角色。后端同时检查租户模块许可、临床角色和患者级权限；仅看到按钮不等于获权。文员不能通过新入口获得临床写权限。Core 会话只能访问本次绑定评估，不能创建独立管理员、换绑患者或跨租户；独立账号也不能绕过 Core 直接访问其绑定评估。

进入凭证 60 秒有效、仅可使用一次，兑换后从地址栏清除；不传 Core 登录 Token。工作区会话固定 10 分钟，过期后从主系统重新进入，已保存的数据不丢。权限撤销对新入口立即生效，已发出的短会话最长残留 10 分钟；接收/复核仍实时检查 Core 权限。

## 完整操作路径

1. 康复管理 → 患者 → 对应患者/周期 → 动作评估，新建或打开记录。先确认患者、周期及视频保存授权。
2. 进入详情的“原生运动学工作区”标签。点击“获取工作区访问入口”，在 60 秒内点击生成的单次链接。
3. 工作区显示主系统机构/患者/动作评估编号，不能手工换绑。上传 OpenCap ZIP，保留 MOT、TRC、缩放 OSIM、Geometry 及需要复核的处理后视频目录。超过试次/体积限额应拆分附件，不取消安全限制。
4. 等待读取完成后“核对资料”。所有原生坐标保留；按部位分组，逐页查看多曲线、左右对照、精确值；TRC 标记点单独使用自己的时间轴。完整原生姿态分块加载，数据缺失/约束失败不补假姿态。
5. 查看候选关键帧，或对当前采样/重点区间取帧。每次最多 24 个时刻；长试次可分批。每路视频偏移单独填写。默认未确认同步，只有核对画面和采集依据后才能勾选确认并填写说明；文件名或时间轴匹配不能自动批准同步。原片不修改。
   处理后视频支持按需播放（每机位最多 64 MiB），可看浏览器实际解码帧 PTS。视频默认独立；确认偏移并保存后才正常联动，未确认时的“候选联动预览”必须主动开启，不能当成已确认同步。大视频仍可提取关键帧，不截断、不自动外发。
6. 保存所选坐标、重点区间、标记、试次可用性及说明。不可量化试次的结果要拒绝或改为无效，不得以实测值同步。未知单位、校准缺证等提示不会因为点“可用”而消失。
7. 逐项采纳/拒绝候选数值，完成每个附件复核，点击“确认数据”。需要解读时仍按手工 GPT 往返和原签发流程处理，不自动外发资料。
8. 点击“提交已确认结果至主系统收件箱”。这是明确提交，不是自动覆盖。返回 Core 标签点击“接收已提交的评估结果”。相同修订重复接收是幂等的；同修订不同哈希拒绝，机构/患者/周期/输入修订不符拒绝。
9. 在接收历史选择一个版本，查看数值、来源哈希和试次复核说明；填写临床复核结论并“确认此版本复核”。此操作不自动改写现场评分、不自动签发主系统报告。原评估报告继续走现有审核签发流程。
10. 数据修正后旧解读失效，重新确认后提交新修订；旧接收版本和复核记录保留。主系统输入修订/患者/周期已变更时拒绝旧绑定，需建立新的动作评估，不能偷偷把旧结果套到新患者。

## 备份、故障与验收

- 同时备份主系统数据库/附件及独立工作区完整私有目录（数据库、不可变原件、派生资源）。只复制程序不等于迁移数据。不要把备份、服务令牌和临床资料提交 Git。
- “未配置服务”：检查三个连接环境变量以及两边一致的令牌，修改后重启相应服务。
- “没有权限”：核对模块许可、临床角色、患者权限和上述专门权限，重新登录/进入，不关闭权限校验。
- “凭证过期”：回 Core 重新获取，不复制旧链接给其他人。
- “输入修订不匹配”：不要改数据库绕过，检查是否修改了主评估或患者归属。
- “无视频”：检查 ZIP 目录、处理后 `_sync.mp4` 文件及 Core 视频授权；不要读 pickle 来猜同步。
- 模型显示加载中：等待对应姿态块；失败可重新选择采样，曲线原值仍在。资源哈希不一致应检查备份/磁盘，不关闭校验。
- 导出坐标 CSV、SVG、原生模型截图及数值/关键帧 ZIP。素材包明确不是临床报告，未确认同步的画面继续标为候选。

自动化：Java 17 下运行 `mvn -pl yudao-module-rehab -am test`；可设置 `REHAB_WORKSPACE_TEST_REPO` 指向独立工作区以启用真实 Java→Python 隔离通信测试。生产库不参与该测试。还需执行 Web 安全测试、隔离后端构建、内部前端构建、迁移守卫；跨平台/业务部署验收须另外核验，不能由本机合成测试替代。
