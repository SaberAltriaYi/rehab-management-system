## 代表性合成流程，不是完整临床验收

通过真实验证码登录及证书校验，执行了：患者建档、Episode、计划、任务、代打卡、复评触发、合成运动数据上传、人工 YBT 输入、异步 Java→Engine 计算、审核、签署、患者版／治疗师版 DOCX 导出。

- YBT 合成数据结果为双侧 81.48%，DOCX 内确实包含已审核数值，不只是空壳 ZIP。
- 缺失模型元数据时质控失败；缺失疼痛记录时拒绝评分审核。补齐明确的合成输入后重新计算，未修改门禁。
- 未实施完整 FMS 现场观察的项目标为不适用，FMS 总分保持空值，不能解释为 0 分或完整 FMS 验证。
- 匿名、外租户访问报告被拒绝；未确认签署被拒绝；已签署记录的直接输入修改被拒绝。
- 切换后重新导出 DOCX，患者版和治疗师版的冻结内容 SHA 均保持不变；切换记录、阶段检查与合成 DOCX 保存在本机隔离证据目录，不进入源码仓库。
- 发布镜像的浏览器检查中，平台、患者、计划、动作评估、打卡、复评触发六个页面及初始 API 通过。平台超级管理员访问仅限 `tenant_admin` 的员工邀请接口得到 403，与后端角色边界一致；机构管理员的员工页面正例仍需独立验收。原始七页 smoke 的 6/7 结果保留，不改写成七页全绿。

这不覆盖所有协议、所有按钮、完整多角色／患者端流程、真实设备采集、OpenCap 在线账号链路或真实临床验证。
