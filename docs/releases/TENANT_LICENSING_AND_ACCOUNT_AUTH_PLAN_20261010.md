1. **跨互联网多设备访问**：工作室可以让获得授权的员工从异地/多终端访问；必须新建零信任远程入口和严格的设备/会话策略，不将当前 `127.0.0.1:8080/8443`、Docker API、MySQL 或 Redis 直接开放公网。授权中心是**控制面**，不默认承载病历数据；远程员工通过经身份认证的加密数据通道连接工作室业务面。异地连接和纯离线状态不能被错误承诺为同时可用。
2. **员工席位由授权单决定、无统一默认上限**：每张许可可由所有者签发任意正整数 `seatLimit`；显式签名的 `null` 才表示该张许可无限席位（可选），空白/缺字段不得视为无限。计量在用人类员工账号，禁用账号释放席位；员工终端数量与业务部署实例数量另行独立配置。
3. **72 小时离线宽限**：只对**先前明确批准并成功验证过**的租户有效。在线验证刷新签名租约；离线文件包含所有者签发、**最长 72 小时**的短期授权证明。超期拒绝新的正常业务会话/写操作，保留安全的身份校验/合法数据迁出与必要临床应急流程（需独立审计和责任审批）。完全离线无法实时撤销，也无法远程访问异地工作室主机。

## 一、商业与权限目标

**工作室必须先经软件所有者批准、取得有效租户许可，才可使用正式康复业务功能。** 单凭安装成功、本地租户管理员账号或修改数据库 `system_tenant.status/expireTime/accountCount`，不能视作有效许可。授权体系与业务账号/租户行级权限并行，二者全部满足才能访问数据。

划分三个信任边界：

1. **软件所有者授权中心（控制面）**：独立的所有者身份、MFA、审批与签发密钥、许可管理及不可抵赖审计；不直接读取工作室病历。
2. **工作室租户（业务面）**：安装主机、租户实例、机构管理员及其员工账号；不可自行签发许可证、修改额度/有效期或将租户提升为所有者。
3. **员工及患者（数据面）**：账号认证、角色菜单、最小权限、已实现的患者行级隔离；尚未批准的患者本人/未成年人入口继续关闭。

## 二、拟建功能清单

### A. 所有者独立授权管理后台（P0）

- 独立所有者登录（建议 FIDO2/TOTP MFA），和本地租户 `admin` 账号分离，不复用租户 1 超级管理员作授权所有者。
- 工作室登记、提交申请、人工审核、拒绝/批准、许可签发、续期、扩容、暂停/恢复、撤销及设备解绑/换机审批。
- 按租户配置有效期、员工席位数、安装主机数、可用功能模块、版本范围；许可号、租户永久 UUID、状态和历史变更完整可查。
- 审计授权人、操作时间、变更前后信息及原因；高风险撤销/密钥轮换支持额外确认，紧急联系和灾难恢复规范。

### B. 工作室首次安装与激活（P0）

- 保留现有 Rust 启动器的 Docker 预检、一次性配置和安全备份；首次启动为 `UNLICENSED`，业务页拒绝访问，但可以查看许可状态、登记工作室、提交激活申请和诊断。
- 生成随机安装实例 ID 与本机密钥对；向授权中心提交最低限度元数据（租户 UUID、实例公钥/摘要、产品版本、必要的联系资料），**不发送病历、患者身份、临床影像、视频或报告**。
- 推荐在线审批后获取已签名的短时许可凭证/租约；支持所有者生成的 Ed25519 签名离线许可证文件，并在无网络环境手动导入。
- 展示状态 `UNLICENSED/PENDING/ACTIVE/GRACE/EXPIRED/SUSPENDED/REVOKED/INVALID`、原因、到期日期、额度和最后验证时间；提供续期与联系授权者入口。
- 不允许租户通过自改 `system_tenant` 字段绕过许可；不允许未批准租户默认自动试用。过期或中止状态应有可审计的安全维护通道，供凭证校验后的加密备份/数据合法迁出，不能删除、隐匿患者数据。

### C. 工作室账号管理（P0）

- 激活后由机构管理员管理员工账号：邀请/新增、禁用/离职、重置凭证、角色分配、最小权限、登录日志、活跃会话撤销。
- 按**唯一在用员工账号数**消耗许可席位；禁用账号释放席位，禁止通过重复用户名/Token 规避配额。初始建议支持工作室管理员、治疗师和审核人员三类，复用现有 RBAC。
- 更改启动器内置超级管理员账号、危险导入/删除、设备换绑前要求当前管理员再次认证并完成明确二次确认；所有者不能因持有授权密钥自动拥有患者数据读取权限。
- 患者端和未成年人监护/临床签署功能不随软件许可证自动解锁；独立的临床/身份门禁照常适用。

### D. 双层服务端强制校验（P0）

- **Java 服务端强制**：账号密码登录、Token 刷新、已持 Token 的所有受保护 API、上传下载/附件、报告、动作评估、后台任务、导出/导入、租户管理关键接口都验证：`许可证状态 AND 用户有效 AND RBAC AND 租户/患者数据权限`。
- Rust 启动器展示/安装与激活状态并二次校验许可签名，但不以按钮禁用代替 Java 的服务端拒绝；拒绝原因结构化、返回业务错误码及无敏感数据。
- 精确定义允许的未授权接口白名单：许可申请/状态/更新、登录为授权维护所必需的步骤、TLS 健康检查、经过身份校验的备份迁出/合法数据导出；不把现有通用后台/患者入口意外加入白名单。
- 许可专用数据表和迁移采用新增编号，在当前 001–025 迁移基础上设计，正式编号需与未提交的 SQL 清单核对后确认；绝不在真实业务卷试迁移。

### E. 密码学、网络和本地离线（P0）

- 所有者授权服务器持有签名私钥（密钥管理/安全存储、轮换、审计、最小授权）；安装包内仅包含校验公钥和 key-id，**绝不打包私钥、主密钥或可复用所有者令牌**。
- 凭证绑定租户不可变 UUID、安装实例 ID、期限、产品/版本、可用模块与账号/实例额度；拒绝伪造、重复重放、错误租户、过期、错误机器以及降级绕过。
- HTTPS 双向挑战（实例私钥签名）与签名租约；定期续期，在线可撤销。缓存租约有效期/离线宽限期暂建议 **72 小时**，仅对先前批准的有效租户生效，未批准状态无宽限。
- 离线文件许可属于显式审批后的有限期授权；**脱机时无法保证即时撤销**，吊销在重新联网或许可到期后生效。对时间回拨做合理检测并拒绝明显异常，但不承诺在工作室完全控制其主机/程序时不可破解。
- 数据发送最小化；日志不可记录完整许可证、私钥、完整设备指纹及访问令牌。安全故障原则上 fail closed，同时保护工作室可依法迁出自身临床资料的通道。

### F. 可视化流程（P1 UI，P0 强制逻辑）

- 所有者授权台：待审批、活动许可、到期预警、异常设备、席位/实例占用、许可详情、操作记录。
- 启动器：首次激活向导、授权申请编号/二维码或代码、许可证文件导入、状态及到期提醒、换机申请、故障与续费帮助。
- 工作室后台：账号管理、角色/权限、使用席位、邀请/停用、许可状态只读；不得出现自行增加许可或更改到期日的入口。

## 五、发布准入与禁止事项

- 正式列入 P0 待实现/待验证项：**tenant_license_authorization**、**account_license_enforcement**、**secure_remote_access**。这些目前都是未通过，且不等于原 `security_license`（第三方依赖许可证/SBOM）；未来在同一冻结提交上完成真实证据与脚本接线后才可变为发布 gate。不能暗改原 `prepackage-readiness.mjs` 使其虚假通过。
- 初装、全新租户、未审批、过期、超席位、伪造/复制设备、授权中心离线、许可撤销、管理员会话存续、租户头冒用、历史权限下放、附件下载及报告签署都有可复现的拒绝测试。
- 真实数据库/现有 Docker volumes 禁止试迁移；开发和回归只用合成数据与独立 Compose；现有患者本人登录、未成年人监护、AI 自动诊断/签署、临床 B 版继续受原门禁限制。
- 无代码签名材料、授权审批和临床验收，不发布正式内测安装包；现有 14 项正式阻断仍保留，直到真实证据满足冻结版发布规则。

## 六、当前实施边界（范围已批准）

**获准开展**：详细威胁建模、独立验证器/数据模型与合成安全测试、无业务影响的新模块、新迁移设计与离线用的纯测试密钥对。**尚不得执行**：创建生产签名私钥、开启互联网服务、对旧患者数据库应用 SQL、直接暴露服务端口、未验收就修改线上登录/租户权限、默认授予工作室许可、合并 PR #5、commit、push 或正式发布。

已固定四项业务要求；所有者中心部署位置/域名、证书签发、私钥托管、联网可用性、支付、身份服务与数据跨境政策仍为运营选择，不能捏造或代替所有者完成。研发可以先用本地合成环境推进 L0/L1，不为这些配置阻塞可验证的独立组件开发。
