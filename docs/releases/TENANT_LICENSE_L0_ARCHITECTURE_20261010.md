## 1. 必须满足的业务不变量

**授权条件**（普通业务请求）：

`有效的所有者签名许可 ∧ 有效租约/不超过72小时离线 ∧ 租户/安装实例匹配 ∧ 账号启用 ∧ RBAC ∧ 资源所属租户/患者范围匹配`

服务端执行，不能仅依赖 Vue 隐藏按钮、Tauri 展示信息、数据库中的租户 `expireTime`，也不能使用共享 `admin` 绕过。

- **批准方**：软件所有者的独立运营身份 + 强制 MFA。任何工作室本地管理员只能提交申请或运营自己的员工，不能签发、扩容、延期、吊销、调整密钥或绕过许可证。
- **授权票据**：每租户有永久不可变 `tenantUuid`；系统当前自增 `tenantId` 只用于业务路由和在本机的映射，不作为全局许可证唯一身份；安装实例有不可变 `installationId`，员工 `userId` 与远程访问设备凭据独立存在。
- **席位**：`seatLimit` 从所有者签署授权单生成，任意正整数；显式 `null` 表示此张授权单无限席位，字段不存在或 0 一律拒绝。仅统计启用的人类员工账号（含工作室管理员）；患者/服务身份单列，不可冒充系统管理员释放席位。并发登录数、可访问设备数量不是员工席位数。
- **安装容量**：每许可独立 `maxInstallations`（初始部署默认先规划为 1，但并非用户对设备数的限制）；允许无限多远程员工终端仍需具名身份和策略认证。实例丢失/换机需所有者审核。
- **授权状态**：`UNLICENSED`、`PENDING`、`ACTIVE`、`GRACE`、`EXPIRED`、`SUSPENDED`、`REVOKED`、`INVALID`；不允许未审批自动试用。对过期、吊销、签名/绑定校验失败限制普通业务，禁止静默降级为“演示管理员”。
- **过期/撤销**：不删除临床数据与备份；工作室合法数据迁出需独立安全认证、审计和用途限定。离线时“实时吊销”无法成立，必须由短期票据强制上限约束。患者本人/未成年人登录、专业报告审批、AI签署仍受原门禁，许可签发不得自动开通。

## 2. 信任边界和部署拓扑

| 组件 | 责任 | 网络约束 |
| --- | --- | --- |
| 所有者控制面 `license-control` | 独立 MFA、工单审批、签名与撤销、审计、公开发行者 key set | 只有许可/设备/实例必要元数据；**不接收病历、康复视频、患者诊疗记录**；私钥仅服务端安全托管 |
| 工作室本地 Tauri + Docker | 安装实例注册、展示许可、受控备份/离线更新、后端业务数据 | 继续只绑定 `127.0.0.1`，MySQL/Redis/ Docker socket 不对公网暴露 |
| 工作室 Java 网关/租户许可校验器 | 验证所有者签名租约及当前撤销快照、每个受保护请求作服务端授权判断、附件权限 | 自己计算可信租户身份，拒绝客户端伪造 `tenant-id`；异常 fail closed |
| 远程接入网关（新） | 已授权员工经 MFA 的专属接入、端到端 TLS、短期会话、可撤销设备身份、审计和限流 | 推荐 WireGuard/零信任私有隧道 + HTTPS 反向代理；**公网只能接触接入网关**，不能触及 Docker/MySQL/Redis 或 Tauri 命令 |
| 远端员工终端 | 浏览器或受管客户端、多因素身份认证 | TLS 校验证书、设备/会话撤销、CSRF/Origin/CORS/安全 Cookie，跨租户访问禁止 |

**特别提醒**：现有系统只开放本机 `https://127.0.0.1:8443`，并未交付多设备或远程网关。远程方案作为独立 `secure_remote_access` P0 工作，不直接改变现有 Compose 绑定、CSP、Cookie 或对外端口；VPN/代理/临床隐私审查和操作人员同意完成后才有受控部署入口。异地员工的互联网断开就无法远程访问本地工作室服务；72小时只保证先前已批准的**工作室本地服务**在许可服务器离线时按规则续用，不保证网络物理连通性。

部署决策默认优先 **临床数据留在工作室** + 全程 TLS/私有隧道直达工作室业务服务，避免把患者数据通过授权中心反向代理。如果企业网络需托管中继、边缘网关或云部署，必须先做监管区域、数据处理者、跨境传输、数据驻留与运维权限审查，不能默认“云端只转发不接触数据”等同不存在隐私风险。

## 3. 签名许可协议与 72h 离线边界

两个层次（禁止仅把长年期授权单当在线有效性证明）：

1. **长期授权单 `entitlement`**：所有者签署租户永久 UUID、被允许的实例数、席位、模块、合同到期 `entitlementExpiresAt`、许可证编号及代际；仅代表业务资格，不保证当前未吊销。
2. **短期租约/离线许可 `lease`**：所有者签署固定协议版本、票据 ID、发行者 `kid`、租户 UUID、安装 UUID、员工席位、部署实例上限、模块、发行时间 `iat`、生效时间 `nbf`、`exp`、合同截止和 `revocationEpoch`。**单份租约寿命 ≤72小时**，`exp` 不能超过合同到期。

在线：经实例持有密钥的挑战响应获得签名租约并轮换，后端本地验证公钥，网络短时故障可凭原租约继续使用至 `exp`。离线：所有者专门签发同协议的短期签名文件、经安全渠道导入；独立审批后签发，不能靠客户端“离线申请”自行授权。两种租约绝不可叠加延长 72小时。许可数据库字段的更新本身不刷新租约。无网时不能可靠检测即时撤销；重新联网必须同步最新撤销代际/状态并撤销旧会话。

**时钟防护**：使用系统 UTC 和持久化校验时间/租约序号的只增高水位、时间回拨告警，检测跳变和复制快照；离线文件无法靠单纯自报时钟完全防本地 root 回拨，绝不能声称绝对防篡改。正式高风险发行前评估可信时间锚、设备密钥安全硬件和实际攻击成本。

**密码学协议原型 RHL1（详见独立 Node 验证器）**：签名字符串为 `RHL1.<kid>.<canonical-json-base64url>` 的 UTF-8 字节，附加 Ed25519 签名得到第四段。使用明确签名算法、公钥 pin / key ID、canonical JSON 固定字段与大小上限、整包 UTF-8、RFC3339 UTC 时间戳、签名覆盖全部授权字段。禁止从票据中读取可覆盖可信公钥的 URL、JWK、`alg`；不允许 `none` 算法或忽略附加字段。现阶段的 Node 版本是**离线安全原型/契约测试工具**，不是 Java/Tauri 生产拦截器。

## 5. 状态机与受保护动作矩阵

| 状态 | 正常业务/新登录 | 权限内本地数据安全迁出 | 申请/续期/诊断 |
| --- | --- | --- | --- |
| `UNLICENSED` / `PENDING` | 拒绝 | 仅已有数据的责任人可受控迁出，不得提供匿名导出 | 允许 |
| `ACTIVE` | 许可 + 员工身份/RBAC/租户数据权限全部通过才允许 | 需要再次认证和审计 | 允许 |
| `GRACE` | 已批准租约有效至 72h 截止，可继续经授权的**本地**业务 | 需要再次认证和审计 | 允许 |
| `EXPIRED` / `SUSPENDED` / `REVOKED` / `INVALID` | 拒绝；已有会话和后台任务也必须中止或隔离 | 独立授权维护流程允许合法备份迁出，不删除病历 | 允许最小白名单 |

需要明确拒绝：密码登录成功不代表存在许可证；旧 Token、后台作业、附件直链、病历导出、报告签署、修改租户状态不能绕过；无法辨别合法例外时 fail closed。临床应急越权应设计经两人审核、短期、全量审计的独立人工流程，未实现前禁止无凭证的“应急允许所有数据”。

## 6. API 草图（L1/L2 详细契约须经联调固定）

- 所有者控制面 `POST /owner/v1/studios/applications`、`POST /owner/v1/applications/{id}/approve`、`POST /owner/v1/licenses/{id}/renew`、`POST /owner/v1/licenses/{id}/revoke`、`POST /owner/v1/installations/{id}/replace`、`GET /owner/v1/licenses/{id}/audit`，**只有所有者 MFA 身份可调用**。
- 工作室激活面 `POST /license/v1/installations/register`、`POST /license/v1/lease/refresh`（实例私钥挑战响应）、`POST /license/v1/lease/import`（签名离线文件）、`GET /license/v1/status`（脱敏状态），只有白名单通道允许尚未激活的实例访问。
- 员工管理 `GET /studio/v1/staff`、`POST /studio/v1/staff/invitations`、`POST /studio/v1/staff/{id}/disable`、`GET /studio/v1/license/limits`，服务端身份、租户和席位事务校验。不可用请求统一返回明示的业务授权错误及重试引导，不泄露安装密钥、患者数据。

**安全要点**：严格定义 CORS、CSRF、Origin、TLS1.2+/优先 1.3、Cookie Secure/HttpOnly/SameSite、设备挑战和重放保护；网关配置失误不能使私人管理 API 变成公网可见。管理后台注册/短信/社交登录等现有入口须逐个归类，不能只拦普通 `/login`。

## 7. 验收/故障注入清单（每项要求机器可审计证据）

1. 未登记/未审批租户首次启动只能申请许可，全部真实康复业务不可访问；已有本地演示环境在切换发布策略前需明确迁移策略，不准无意锁死既有用户。
2. 许可证签名损坏、参数追加、重复 JSON 键、错误 `kid`、错误 UUID、错误实例、缺失席位、不合法无限席位、过期、未来签发/回拨、超过72小时、合同截止之前已租约失效，一律拒绝。
3. 两个租户/两个安装实例及并发创建员工账号时不可跨域、不可超席位；强制后端 API、后台任务、文件下载/上传、版本报告与 OAuth2 refresh 分别拦截。
4. 在线轮换/吊销/密钥回收/主机失联，72 小时离线演练；客户端复制实例或本地数据库修改无效。
5. 真机多浏览器、多设备经零信任接入网关访问，客户端断线、设备撤销、Token 盗用、反向代理带入伪造 `tenant-id`、CORS/CSRF 及公网端口探测均按预期拒绝。
6. 启动器危险操作重新认证、备份恢复/导入旧许可/安装实例换机、证书更新、崩溃恢复与安全迁出，不暴露临床资料或密钥到日志。
7. 不变的旧门禁：患者/未成年人入口 HTTP403、临床 B 版与人工审核、Chrome 真机/Windows+Mac 构建、授权/许可证合规、无真实卷变更。**NO-GO 直到同一冻结 SHA 的证据全量通过。**

## 8. 工程接续与依赖顺序

- **当前 L0**：本文件及已批准业务计划；维护源码基线和未合并历史修改。签名凭证协议的 Node 独立原型能使用内存中的合成测试密钥检验基本密码学边界，但**不代表已建所有者授权中心或 Java API 强制拦截**。
- **L1**：单独部署所有者身份/MFA、申请审批状态机、签发/换钥/吊销、签名服务及私钥运营；控制面绝不使用租户 1 超管作为所有者。
- **L2**：合成 DB 新增存储与 Java 纯验证器，接入权限/认证流程，覆盖所有业务 API、后台任务和数据出入口；逐步从影子校验转受控 deny-by-default，严禁靠前端禁用按钮当验证。
- **L3**：Tauri 激活向导和设备本地身份、在线/离线导入、退出/备份/重装以及高危命令重认证。
- **L4**：所有者审批后台、工作室员工/席位管理、审计和授权到期提示。
- **L6**：独立互联网远程网关（可与 L3/L4 并行研发），必须在 L5 最终真机回归前纳入整体安全验收。
- **L5**：完整合成两租户多实例 + 跨互联网安全通道的 Java/Node/Rust/Chrome E2E、签名/吊销/回滚/恢复/监管/临床审计；正式门禁记录拟新增 `tenant_license_authorization`、`account_license_enforcement`、`secure_remote_access`，不能改旧工具将缺失证据伪装为 PASS。

当前尚未获得的运营依赖：你选择的所有者授权域名/云或本地安全服务器、MFA/运维人员、证书和受保护私钥托管方案，以及远程临床网络的数据驻留/跨境处理要求。这些**不阻断本机独立的协议/安全测试开发**，但上线前必须明确。
