## 1. 执行约定

本计划是后续实施台账，不是全部功能完成声明。执行者每完成一批更新任务状态、提交、测试证据、数据影响和下一步。对话结束后不假定后台继续开发。

状态分开记录：待开始 → 设计中 → 实施中 → 代码完成 → 自动化验证 → 已部署测试 → 真实路径验收；阻塞项单列。未开发、未运行、跳过、失败不能记为通过。

每批流程：阅读现状 → 明确边界 → 设计/迁移说明 → 实现 → 测试 → 审查 → 本地提交 → 测试部署 → 验收。推送、部署和数据变更按已确认的目标环境执行，不混用其他工作树。破坏性数据变更仍须另行确认。

## 4. Schema 与数据变更闸门

每一项新增表/字段先说明：目的、与旧模型关系、新增/删除清单、旧数据默认值、回填与校验、索引/唯一约束、权限、兼容期、备份、失败处理、回滚或前滚策略。

优先 additive：revision、Client 映射、附件元数据、快照/版本、业务流水等均在具体设计后确认。当前计划不批准自动重写历史记录。迁移不得依赖重放 001—019；新增迁移需独立测试。

回滚不简单等于 DROP 新表：一旦产生新业务数据，必须设计保留/导出/前滚方案，停止后明确处理。潜在丢失、历史合并或永久删除必须再次确认。
