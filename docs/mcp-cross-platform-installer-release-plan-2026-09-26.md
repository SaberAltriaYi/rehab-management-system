# Windows / macOS / UniApp 完成与安装程序优化：实施增补计划

**记录日期：**2026-09-26。**项目：**`rehab-module-enable-clean`；本文件补充 `docs/mcp-implementation-plan.md`、`docs/desktop-packaging.md` 与 `docs/mcp-rehab-framework-opencap-feasibility-2026-09-26.md`，不把旧阶段性记录改写成已完成状态。

> **本轮范围：仅更新计划与验收标准。未修改业务/安装器/移动端代码，未执行构建、打包、部署、签名或真机测试。**后续实施须先锁定目标 commit、目标环境和数据备份。产品定位：先内部可重现版，再正式发行；桌面端同时需要「本机一体包」与「连接机构服务器的客户端」；UniApp 先微信小程序，随后 Android/iOS；OpenCap 不做全面接入，只规划合法来源样本的文件导入与自建条件评估。

## 1. 已确认的决定和不能越过的边界

| 决定 | 执行含义 |
| --- | --- |
| Windows + macOS 两种安装形态均需完成 | ①本机一体包：保留现有 Tauri v2 启动器 + Docker Compose；②机构内网客户端：**待设计的新发行形态**，连接机构 HTTPS 服务，不复制后端、MySQL 或患者数据库到每台终端。不能把既有本机启动器描述为已实现客户端模式。 |
| UniApp 微信优先 | 首先规划微信小程序的员工侧验证；Android APK 和 iOS IPA 后续交付。`build:mp-weixin` 只是小程序资源，`build:app` 只是 App-Plus 资源，均不等于平台审核通过或 APK/IPA 已生成。 |
| 商业机构真实患者数据环境，希望 CRM/BPM/ERP 尽快全开 | 这是**目标而非可跳过门禁的授权**。任何含真实数据的模块先过备份/恢复、迁移兼容、角色/租户/患者范围、菜单/API 和回滚（或前滚）验证；通过一个开一个，未通过不启用。合成或脱敏副本供联调，禁止在现有业务卷上试错、全表清理或一键全开未审路由。 |
| 当前没有签名证书、发布账号或可验收真机 | 可做文档、构建与自动化准备；Windows 正式签名、macOS Developer ID/公证、微信正式提交与真机验收、Android/iOS 签名包均是**外部资源阻断**。未签名内部包须明确标注 `unsigned`，不算公开发行完成。 |
| 患者登录和外部 AI | 患者登录保持关闭，先改强身份验证、限频/防枚举、绑定与令牌安全存储。未审业务模块、任意 SQL 和真实患者资料不得接入外部 AI；OpenCap 研究云不作商业试用。 |

## 2. 只读基线：现有代码/文档能证明什么

- `desktop/launcher/src-tauri/tauri.conf.json` 已配置 Tauri v2、Windows **x64 NSIS** 的 `currentUser` 安装与 macOS **universal DMG**；业务服务仍由 Docker Compose 在本机运行。`desktop/launcher/README.md` 明示：仅用于本地服务管理，不能用资源占位文件生成交付包。`desktop/launcher/src-tauri/windows/installer-hooks.nsh` 已有普通卸载保留数据的钩子。上述为代码设计，**不是本轮真实安装回归**。
- `docs/desktop-packaging.md`、`docs/desktop-release-checklist.md` 定义了本机运行资源、加密备份、整店迁移、四个固定 Docker 卷、普通卸载保留数据及正式签名清单。历史计划中的 `desktop/runtime/1.0.0`、前端 `dist-internal` 或 preview 产物不得复用为目标提交的新证据；先解决标准 `pnpm build:internal` 的 JSX/Babel 异常，再按目标提交从头构建、做哈希清单和隔离恢复。
- `yudao-ui/yudao-ui-rehab-uniapp/README.md`、`package.json`、`src/manifest.json` 证明现有 UniApp 源码目标覆盖 H5、微信小程序和 App-Plus；**小程序与 DCloud AppID 均为空**。README 明示患者登录默认关闭，原有患者身份验证仅凭手机号和编号、令牌未接入 Keychain/Keystore；当前无签名安装包或平台发布资产。这些是发布阻断项。
- `docs/mcp-implementation-plan.md` 是 2026-09-20 的阶段性台账；`docs/build-verification-2026-09-23.md` 曾记录前端构建通过但全项目 1,129 条类型诊断、后端 36 项跳过。这些数量**不是当前目标提交的复测结果**；须重新分类核对。较新的 OpenCap/G0–G5 计划另见上述架构文件。

## 4. 安装程序优化：两种形态分开设计、分开验收

### 4.1 首次安装与启用体验

- 安装前展示版本、适用架构、部署形态、本机/机构数据位置、网络/磁盘要求及是否需 Docker；提示现有本机服务/卷和备份风险。安装程序只装应用，**启用业务服务**由可观察的首次启动向导执行；不要无提示修改系统防火墙、安装 Docker、配置公网或下载不固定版本组件。
- 本机版提供阶段进度和可复查的错误：Docker CLI/daemon/Compose、磁盘/端口、资源 SHA-256、脱敏初始快照、生成各自独立的机器密钥、本机 TLS、固定镜像、迁移账本、后端/前端健康。失败不留半安装中的患者数据，不把密钥/手机号写入日志；提示最小修复动作并可安全重试。
- 机构客户端第一次只配置受控的 **HTTPS FQDN** 与受信证书、版本兼容和用户登录；不把本机 `127.0.0.1` 或测试服务器固化为终端 API，不允许“跳过证书校验”；服务器不可达时禁止显示上次机构的敏感缓存。两种桌面形态应使用独立的 app/bundle 身份、配置目录、升级轨道和图标/安装包名称，避免客户端升级覆盖本机一体包或连接错患者库。
- 界面与文档使用统一的中文错误编号、诊断导出和人工修复步骤；诊断默认仅含构建信息、运行状态和脱敏事件，用户可预览，无原始患者资料、密钥或认证 Token。

### 4.2 升级、回滚、卸载与保护

- 安装器来源与目标提交统一记录：锁文件/JDK/Node/pnpm/Rust/镜像摘要、构建时间与 commit SHA；从隔离干净目录跑**原样** `pnpm build:internal`，后端、前端、启动器均测完才生成新的 `runtime/1.0.0` 与 `SHA256SUMS`/`BUILD-INFO`。版本号必须与内容一致；不拿旧 `dist-internal`、旧 `preview.3` 或占位 README 冒充。Windows runner 产 NSIS、macOS runner 产 universal DMG；同一源提交与资源清单可追溯，不能凭另一平台构建产物推定本平台合格。
- 升级前确认**数据库 + 附件一致的加密备份**及独立环境恢复；保留旧运行资源与稳定卷。二进制回退与 Schema 回退分开：一旦迁移产生新数据，不能自动降级数据库；须按兼容期和前滚/恢复方案处理。版本不匹配应阻止继续写业务数据，避免旧客户端污染新服务。
- NSIS 普通卸载与 macOS 移走 `.app` 默认保留应用数据、四个稳定卷、备份；卸载器应明确告知后台服务是否仍运行以及重装/迁移路径。彻底删除仅能在应用危险区由有权用户逐项确认，并核对**仅本产品固定资源**。机构客户端只清除其自身缓存，不接触一体包的数据/卷。
- 对首次、失败后重试、跨版本升级、重装、普通卸载、显式彻底删除、端口冲突、Docker 缺失/停机、断网、证书错误、备份损坏和错误口令逐项做可重复用例；记录设备/OS、目标 SHA、操作、预期、实际和产物哈希，不以浏览器模拟代替设备。

## 5. 微信优先的 UniApp 实施路径

1. **安全先于登录：**先改造后端患者身份凭据、绑定校验、请求限频、防枚举、令牌撤销/过期；前端与服务端联测，患者登录开关继续为 `false`。员工端也需验证验证码/微信兼容、角色/患者范围和会话退出；真实病例只在获授权安全环境展示。
2. **网络与主体：**明确小程序 AppID 归属、机构 HTTPS API 域名、合法 request 域名、证书和业务主体隐私申报。**内网-only 后端与微信真机访问可能冲突**：不能写 `localhost`/私网 IP 当作正式小程序 API，也不能为省事把含患者数据的后台直接暴露公网；需独立设计可达且受控的接入层，否则小程序只停留在本地构建/模拟，不能发布。
3. **分段验收：**先 type-check、依赖/安全审计和 `pnpm build:mp-weixin`；得到 AppID 后用微信开发者工具、体验版、真实微信设备、平台审核逐层证明。未完成正式审核、真机及数据治理前，小程序标注“构建就绪/待平台资源”，不得标“已发布”。
4. **再做 Android、iOS：**同一后端安全闭环通过后，分别处理 DCloud AppID、包名/Bundle ID、签名归属、Keychain/Keystore、设备可访问 API、APK/IPA 生成、升级/卸载与真机矩阵；不可用 Web/H5 预览替代原生验收。患者登录在强认证和相关真机测试通过前继续关闭。

## 6. 并行工作、G0–G5 对齐和启用顺序

| 层次 | 后续工作及通过条件 | 不能提前声称 |
| --- | --- | --- |
| G0／发行底座 | 锁定权威仓库/目标 SHA、数据负责人/部署环境；从零修标准构建异常、TypeScript 基线与跳过测试；备份真实数据并在隔离副本验证恢复；归档各环境权限/TLS/AI 禁用清单 | 旧构建通过、既存产物和未复核的 36 项跳过不等于新提交通过 |
| 桌面内测主线 | 后端、前端、启动器测试 → 新 `runtime/1.0.0` → 本机 Win/Mac 干净设备 → 机构客户端独立实现/验收 → 安装/升级/卸载证据 | 未签名或未公证包、未真机验证的客户端不是正式 Win/Mac 发行完成 |
| G1/G2／业务主链 | SFMA 草稿/并发/自动保存，评估/报告，安全原件/多格式资料包；统一 Client/CRM/预约；逐模块处理 BPM/ERP 和运营闭环，保存角色/租户/设备/恢复证据 | CRM/BPM/ERP 菜单全开不等于已审查，真实数据环境不得先启用再补权限 |
| G3/G4／OpenCap 边界 | **G3 仅合法来源、许可明确的 OpenCap 格式样本文件安全导入**；不接 Stanford 研究云、不上传真实患者数据；G4 自动动作/步态量化试点暂缓；合法自建仅审查许可、采集端、依赖模型、GPU、隔离、成本与数据位置 | 不把源码 Apache-2.0 许可当作云服务/采集 App 商业许可，不宣称自动诊断 |
| G5／纵向流程 | 人工确认的评估→报告→计划→执行→复评/结案；微信员工端优先在合规网络完成验收，Android/iOS 后续；跨设备/弱网/租户/恢复回归 | 微信本地构建、患者开关打开或 H5 预览都不能代替平台发布/临床业务验收 |
| 公开发行（G6/最终门禁） | 签名、公证、平台主体资质、HTTPS 域名/AppID、真机与微信审核、发布手册及最终责任人签署 | 无证书/账号/设备时保持阻断，绝不借 `unsigned` 内测包宣称正式发行 |

**正式启用顺序：**先备份与隔离副本，完成最小安全/迁移审查；在真实患者数据环境对 CRM、BPM、ERP 逐模块开通且留回滚/停用路径；同时推进桌面构建与安装器改进。未审模块、任意 SQL、真实患者资料继续不接外部 AI。移动患者端等强认证之后才考虑开放。

## 7. 交付台账与待用户/责任人提供的资源

每个任务按 `设计中 → 代码完成 → 自动化通过 → 隔离环境验收 → 真实设备/平台验收 → 签署交付` 记录；缺证据只能写“阻断/未验证”，不得写“完成”。交付包应含：目标 commit、构建/测试日志、依赖清单、安装器及 SHA-256、版本/迁移清单、签名验证、干净设备矩阵、备份恢复、升级卸载记录、权限/租户负例、遗留问题与负责人。

- **当前缺失：**目标提交/明确版本冻结（实施开始时锁定）；Windows 可验收设备/runner 与代码签名证书、时间戳服务；macOS Intel/Apple Silicon 可验收设备、Developer ID 与公证账号；微信小程序 AppID/主体、合规可达的 HTTPS 域名和真机/审核资源；Android/iOS 包名、签名与测试设备。没有这些资源，先完成内部代码与自动化准备，外部发行状态保持阻断。
- **下一次可执行批次（待明确开始）：**只读锁定目标 SHA 和当前阻断 → 检查隔离备份/恢复 → 复现 `pnpm build:internal` JSX/Babel 异常并提出最小修复 → 按目标提交重建运行资源与测试；另开机构客户端及微信网络/身份安全设计。**本轮不执行该批次。**
