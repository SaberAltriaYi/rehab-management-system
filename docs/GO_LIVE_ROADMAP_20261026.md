# 康复系统群完善与分阶段上线方案

日期：2026-10-26。性质：基于当前代码、运行制品与测试的实施建议，不是生产验收通过证明。

本轮只执行隔离自动化测试、只读运行核对和规划整理；不新增业务患者、不扩大现有账号权限、不自动签发临床报告、不启用外部 AI、不部署公网服务、不发布安装包。当前主系统沿用 `feature/reporter-engine-assessment-20261013`，未切换或创建分支。

## 1. 结论与发布范围

建议先交付单工作室、约 3 名治疗师使用的内部稳定版，再开放经授权的患者 H5，最后推进多机构和跨平台正式分发。不得同时把 CRM、ERP、SaaS、自动评分和云端 AI 全部打开。

- 内部版第一条主线：患者 → 疗程 → 现场评估 → OpenCap 导入与质控 → 治疗师复核 → 报告/处方 → 复评。
- 患者版第二条主线：正式患者登录 → 本人已下发计划 → 逐组训练 → 疼痛/RPE/异常反馈 → 风险复核 → 回传 Core。
- 管理版第三条主线：机构/人员/权限 → 会员准入 → CRM 部门认领与转接 → 经营统计。
- 算法第一版只交付可追溯的运动学分析与候选事件，不能把模型坐标直接宣称为临床 ROM、FMS/NASM-CES/SFMA 自动评分或诊断。
- 目前适合继续内部验证；**完整业务验收、患者端正式开放、远程正式部署和新安装包发布仍为 NO-GO**。

## 4. 功能完善顺序

### G0：补齐测试条件与版本冻结

1. 经授权建立最小权限治疗师/患者测试身份和明确标记的合成患者，或使用用户提供的现有测试身份；不扩权当前账号、不动其他机构数据。
2. 在隔离环境跑通患者 → 疗程 → FMS/NASM-CES/SFMA → 报告 → 训练 → 复评；增加必填、重复提交、删除约束、无权访问、跨机构、数据修改后旧草稿失效等用例。
3. 使用已授权 OpenCap 样本核对 Core 入口、票据过期/重放、工作区复核、回传、主系统查看及旧修订拒绝。模拟授权与真实临床有效性分别记录。
4. 固定每个服务的 commit、构建摘要、迁移版本、接口版本、开关矩阵、已知问题；集中证据索引，避免旧报告混作本轮证明。

验收门槛：核心操作用例逐条有证据；已发现 P0/P1 不能留到患者开放后。未授权部分标为阻塞，不填“通过”。

### G1：身份和跨系统业务闭环

1. 补患者正常登录和绑定：支持机构授权身份入口、退出、过期重登；H5 同源/严格来源交接，不在 URL/诊断日志携带长期 Token。
2. 患者仅能查看已下发且属于自己的训练；不得浏览完整动作库、组课、修改处方、为他人签到。
3. 贯通签发处方 → 审核动作映射 → 计划快照 → 逐组训练 → 疼痛/RPE/异常 → 待复核 → 已处理 → Core 复评；没有映射/无权益/错误租户必须拒绝。
4. 结果同步携带稳定 ID、修订、来源摘要和幂等键；失败有可见队列、重试和人工处理，不能重复导入或静默覆盖。
5. 会员冻结/到期时如何保留训练历史、是否停止新计划必须形成明确业务规则；风险事件不能因权益到期丢失。
6. 动作库由 HEP 统一维护、Core 引用：动作名称/版本、媒体使用权、器械、剂量参数、注意事项及审核状态齐全；模板和动作变更不追溯修改已下发处方快照。患者端只展示处方所需动作，不能把“会员动作库”做成无约束自由组课入口。

验收门槛：治疗师、机构管理员、患者、监护人四类身份分开测试；患者拒绝用例与正常用例同等重要。只有本阶段通过，才开放患者试用。

### G2：管理系统启用与边界

1. CRM 先做候选制品与隔离双部门验收，再显式启用；共享目录只展示最小字段，部门私有数据和历史私有备注不随意共享。
2. 转接采用发起/接收/拒绝/取消状态机及事务，不用改负责人绕过；导出、统计、合同/联系人关联入口也验证部门边界。
3. 会员中心聚焦身份、权益、处方准入和服务记录；第一版不引入与康复交付无关的商城/营销/支付流程。
4. Owner 与机构管理员保持独立登录边界；高危授权/撤销/恢复操作重新认证和审计。多机构商业化之前单独验收全部入口，不用本地单测替代。

## 6. 算法升级路线与临床边界

当前运动学原生输入/曲线/模型姿态已经存在；`motion.py` 的事件逻辑主要是起止和信号极值，不是已验证的落地、步态或动作分期识别。建议分四层升级：

### A1 数据质量优先

- 数据包清单、来源 SHA-256、输入和引擎版本、模型和网格、坐标类型/单位、时间轴、缺失率、跳变、可用视频和同步状态统一呈现。
- 有标记点与模型对应、缩放及足够输入时才计算有意义的残差；资料不足明确“无法评估”，不编造质量分。
- 缺校准、遮挡或模型冲突进入待复核，不只显示一个绿色成功标识。自动候选同步不能自动成为人工确认同步。
- 固定原始结果；任何滤波、重采样、插值都作为派生层，记录参数与版本，禁止跨大段缺失补点。

验收：缺模型、错单位、非均匀时间、丢帧、缺坐标、零值、非有限值、损坏 ZIP、解压炸弹、错误网格与未知耦合坐标均有负例；原始值逐项可对照。

### A2 分动作识别与定量

- 首批先选择临床实际采集且有足够标注的深蹲/单腿蹲，不一次覆盖所有项目；周期、静止段、幅度与持续时间候选可人工修改。
- 在经确认的分析区间计算模型坐标幅度、峰值及发生时间、左右差与重复稳定性；对时长归一化曲线保留原始秒轴、事件映射和计算定义。
- 速度/加速度只有在采样与处理方案通过噪声验证后输出；不给所有动作套同一固定滤波参数。近零分母、不同单位、缺失侧别时不计算误导性对称指数。
- 只有经数据与标注验证后才增加步态/着地事件；没有力台/可信动力学结果，不从普通关节角度推导“实测地面反作用力”或关节负荷。

验收：治疗师标注与算法候选逐试次对照，记录边界误差、漏检/误检、重复性和不适用场景；合成精确值测试与真实测量有效性分别验收。阈值在测试集冻结前由负责人确定，不凭空承诺准确率。

### A3 临床规则与人群适用性

- FMS、NASM-CES、SFMA 继续由 Core 原表单记录；规则逐条绑定来源/版本/适用人群/必需现场观察，不能从少数角度补齐未观察项。
- 儿童与青少年体态/基础能力、青少年专项运动员、成年人运动康复分别建立解释模板；没有可信参考数据，不输出百分位、疾病诊断或“正常/异常”的确定结论。
- 人工复核每个试次可用性，保存接受/排除及原因；复评只有相同协议/侧别/坐标定义/处理版本可比，不可比时明确说明。
- 升级算法后生成新结果版本，不覆盖已签发报告，不默认批量重算历史患者。

验收：授权数据集与人工标注、评价者一致性、独立留出集和失败案例；当前单个受试者的 15 个试次仅为软件证据，不足以建立跨人群临床有效性。

### A4 报告与可选 AI

- 先完成确定性报告：数据来源/质控、各评估原始记录、定量表、全曲线索引、选定图帧/姿态、限制、治疗师复核意见；输出治疗师详细版和家长/患者沟通版可编辑 Word。
- 原始值、设备/模型派生量、规则推断、人工意见在界面及报告中分开标记；没有数据的板块留空或写未测，不让语言模型补数值。
- 默认保持自动云端 AI 关闭；现有手工授权导入导出链路可保留。后续启用需要独立同意、未成年人监护授权、最小化/去标识、供应商数据策略审查和撤销处理。
- AI 只生成可复核草稿，绑定修订与来源摘要；不能签发、自改阈值或自动下发患者处方。报告定稿仍依现有人工审核权限。

算法依据：OpenSim 官方文档明确区分模型坐标、实验标记点误差与坐标误差，并要求处理单位；因此上述“质控在前、量化与临床评分分层”是本项目设计选择，不是声称 OpenSim 自动保证临床有效性。

## 7. 安全、性能与部署上线门槛

以下为建议验收目标，尚未实测达到；不得作为当前 SLA 对外承诺。

- 负载：约每天 3 人次评估、3 名治疗师同时使用；覆盖 3 个并行分析任务及日常 Core/HEP 查询，重任务排队、不拖垮登录和保存。
- 时限：在约定的 OpenCap 包体积/试次/视频预算和指定 Mac/Windows 硬件上，95% 有效测试任务在导入后 60 分钟内得到可复核草稿；先测基线，超预算展示预计队列，不算静默成功。
- 常规查询建议 P95 ≤1 秒、普通写入 P95 ≤2 秒；大文件/解析/报告另列指标，监测内存、CPU、队列长度和磁盘余量。不给小样本平均值冒充压力测试。
- 备份目标建议 RPO ≤24 小时、RTO ≤2 小时，需工作室确认业务损失容忍度后用真实规模恢复演练验证；原件、数据库、附件和密钥恢复分别设计。
- 应用、运动引擎及 HEP 形成不可变版本制品/清单，升级前备份；失败保留日志与数据；迁移不假定可逆，不使用删卷回退。
- 当前 Vite 开发前端不能作为正式部署。改为构建产物 + 正式反向代理，回环服务仅由明确网关连接；局域网使用指定 IP、TLS 和已信任证书，不绑定任意地址，不关闭 TLS 验证。
- 患者居家访问与工作室局域网是两种部署边界：患者 H5 远程开放前另行验收可信 HTTPS 网关、身份、频率限制、授权与撤销；不让患者使用 `127.0.0.1`，不暴露 MySQL/Redis，不自动设置路由器公网转发。Owner 入口与患者网关保持隔离。
- 现有 Compose 的 MySQL/Redis 已固定版本，但业务后端/管理端仍使用本地 `:latest` 标签；正式发布应改为固定发布版本或摘要并记录镜像清单，避免本地构建标签覆盖。不以“不是基础镜像”作为忽略制品可追溯性的理由。
- 数据库、附件、原视频与派生图帧分层计量；建立配额、磁盘余量和备份空间告警。临时任务/派生缓存可按保留策略回收，源资料与已签发证据不得静默删除；相同来源去重仍须保留每位患者的权限和来源关系。
- 依赖锁定、SBOM、漏洞与许可证审查、密钥扫描；按风险分批更新框架/JDK/Node，不把全栈大版本升级与首版业务发布混在一起。本轮未做完整依赖漏洞审计。
- 认证、租户/部门/患者对象权限、会话过期、上传、CSRF/XSS、诊断脱敏、备份和恢复按 OWASP ASVS 要求建立可执行清单，不把健康接口返回 200 当安全验收。
- 正式环境启用前，轮换曾在聊天、测试说明或日志中出现的账号密码、TOTP 种子和其他凭据，撤销旧会话；本轮不在文档中复述这些内容，也未擅自重置现有用户身份。
- Rust 测试在有固定工具链的构建环境跑通；打包 Core + HEP + Python/OpenSim 的真实运行依赖、资源与迁移，而不是只复制旧的 Core 安装包。Mac/Windows 原生依赖和许可证分别核验。
- Windows x64、Mac Apple Silicon/Intel 从干净设备安装、启动、升级、重装、卸载保留数据逐项实测。为 macOS 配 Developer ID 签名/公证，为 Windows 配受支持的签名方式；签名不等于保证 SmartScreen 永不提醒。
- 安装包、SHA-256、构建 commit、迁移版本、已启用模块、签名状态和已知限制一并发布；CI 全部必要任务成功后才形成候选发布，先 draft 再人工验收。

## 8. 排期、依赖与交付物

以下是粗略工程工作量，不是固定日期承诺；以 1 名全栈工程师、可用构建/QA 环境，以及治疗师按时提供标注和反馈为前提。阶段有依赖且部分可交叉，不能机械相加成确定交付日。

| 阶段 | 参考工作量 | 主要交付 | 进入下一阶段条件 |
| --- | --- | --- | --- |
| P0 测试条件/冻结与缺口核对 | 2–3 工程工作日 | 权限/场景矩阵、授权测试数据、失败清单、版本与开关清单 | 获准测试身份；确认 EMP/EPM 含义及首版范围 |
| P1 身份与核心闭环 | 5–8 工作日 | 患者登录、Core—运动—HEP 正向链路和负例证据 | 核心 P0/P1 修复并回归；患者不能越权 |
| P2 UI 与稳定性整理 | 5–8 工作日 | 共用状态/视觉规范、工作区/患者手机界面、截图和易用性报告 | 角色任务和手机视口验收，数据与权限不回退 |
| P3 算法 A1/A2 及报告 | 8–12 工作日 | 质控、候选事件、可追溯量化、图文 Word 与冻结标注集报告 | 基线/留出集结果与限制通过治疗师审核 |
| P4 管理模块与发布工程 | 5–8 工作日 | CRM 候选启用、会员权益回归、统一运行制品、CI、签名/恢复证据 | 无阻断缺陷，Win/Mac 与升级恢复实测通过 |
| P5 受控试运行 | 至少 1–2 周观察期 | 每日风险/失败/反馈台账、恢复抽查、正式上线决定 | 关键失败均关闭；治疗师与运维共同确认 |

A3 跨人群临床规则验证和 A4 云端 AI 属于后续独立升级，不把它们塞进“快速上线”承诺。若首发暂不启用 CRM/Owner 商业授权，可将其保持关闭，不阻塞已满足门槛的单工作室内部版。

每阶段交付必须包含：修改清单、测试与失败/跳过原因、构建标识、升级/恢复步骤、剩余风险；版本号由发布范围决定，不在未完成验收时发布“正式版”。

## 9. 最终 Go / No-Go 清单

- [ ] 专用身份/合成患者授权明确，测试痕迹可区分；无跨机构数据混用。
- [ ] 患者到复评的 Core 主线通过，报告与版本操作可恢复。
- [ ] Core → 运动工作区 → 人工复核 → 回传链路及拒绝/重放/过期通过。
- [ ] 正常患者登录、本人计划、训练、疼痛/RPE、风险、治疗师复核及同步通过。
- [ ] CRM/会员/Owner 按拟发布范围分别验收，未验收模块明确关闭。
- [ ] UI 角色/视口、键盘及错误恢复完成实际浏览器和截图检查。
- [ ] 算法原始值、质控、版本、人工复核及失效规则通过；无夸大临床有效性。
- [ ] 必要单元/集成/安全测试零失败；跳过均逐项评审，禁用测试缺口已补证。
- [ ] 固定制品、依赖/许可证/漏洞、TLS、秘密与诊断脱敏检查完成。
- [ ] Windows/Mac 安装、升级、重装、卸载保留数据及备份恢复通过。
- [ ] 签名/公证、安装包摘要和发布材料明确，CI 与实机制品一致。
- [ ] 试运行完成，业务和运维负责人批准；记录剩余风险接受人及期限。
