# 康复管理系统后台管理使用说明

本文面向工作室负责人、康复治疗师和文员，说明如何进入“运动康复评估与业务管理系统”后台，
以及如何完成从患者建档、评估、报告、训练到复评的日常操作。

> 本系统仅用于工作室内部康复评估和业务记录，不替代医疗诊断。V1.0 默认关闭 AI、商城、
> 支付、IoT、BPM 等未交付模块；不要在后台自行启用这些模块。

## 1. 如何进入后台

### 1.1 在安装了桌面版的电脑上进入

1. 启动 Docker Desktop，等待界面显示 Docker Engine 已运行。
2. 从 Windows 开始菜单或 macOS“应用程序”打开“康复管理系统”。
3. 在启动器中点击“启动服务”。首次启动需要拉取固定版本镜像和初始化数据库，耗时取决于
   网络速度；不要在初始化过程中退出 Docker Desktop。
4. 等待 MySQL、Redis、后端和管理端均显示健康。
5. 点击“打开系统”。默认后台地址为 `https://127.0.0.1:8443`；如果在启动器中修改过端口，
   以启动器显示的“当前访问地址”为准。

关闭启动器不会停止后台服务。需要停止服务时重新打开启动器并点击“停止服务”；正常停止和
重启不会删除患者数据。

### 1.2 从同一 Wi-Fi/局域网的手机、平板或其他电脑进入

桌面版默认只允许安装电脑本机访问。局域网访问必须先按
[局域网一键部署文档](../deploy/lan/README.md)在一台固定的部署设备上完成安装，然后：

1. 确认部署设备保持开机、Docker 服务正常，且与成员设备连接同一可信局域网。
2. 在成员设备打开 `http://部署设备IP:8080/ca.crt`，安装并信任工作室局域网 CA。
3. 在浏览器打开 `https://部署设备IP:8443`，例如 `https://192.168.1.100:8443`。
4. 使用管理员分配给本人的账号登录，不要在多台设备共用 `admin`。

必须使用安装时选定的具体私网 IPv4。不要使用 `0.0.0.0`，不要配置路由器公网端口转发，
也不要把后台暴露到互联网。

### 1.3 浏览器显示证书提醒

- 本机首次访问时，证书由启动器在本机生成。只有在地址确实是
  `https://127.0.0.1:8443`（或启动器显示的本机端口）时才继续。
- 局域网设备应先安装部署设备提供的 CA，再访问后台。不要习惯性忽略证书警告。
- 长期使用应按[证书安装说明](../deploy/internal/manual/CA_INSTALLATION.md)完成系统级信任。
- 禁止全局关闭浏览器、操作系统或命令行工具的 TLS 校验。

## 2. 首次登录

登录页需要填写以下信息：

| 项目 | 桌面版 | 局域网一键部署版 |
| --- | --- | --- |
| 租户 | `工作室内部` | `工作室内部` |
| 用户名 | `admin` | `admin` |
| 初始密码 | 启动器首次启动后显示的 16 位随机密码 | 部署设备本地 `deploy/lan/FIRST_LOGIN.txt` 中的随机密码 |
| 地址 | 启动器显示的当前访问地址 | `https://部署设备IP:8443` |

操作顺序：

1. 先安全保存一次初始密码，不要截图发到群聊，也不要上传到 GitHub 或网盘。
2. 输入租户、用户名和初始密码完成登录。
3. 点击右上角头像，进入“个人中心 → 密码设置”。
4. 输入旧密码和 4–16 位新密码，保存后退出并重新登录验证。
5. 桌面版确认新密码有效后，可在启动器点击“我已保存，停止显示”；局域网版应删除部署设备
   上的 `FIRST_LOGIN.txt`。

新密码应由大小写字母、数字和符号组合，不要使用姓名、手机号、生日、工作室名称或其他容易
猜测的内容。基础设施密码由系统单独生成，不受管理员登录密码 16 位上限影响。

如果忘记初始密码、初始密码已经隐藏或旧预发布包提示密码长度错误，不要删除数据库卷，也
不要重新初始化系统。先查看[桌面端故障排查](desktop-troubleshooting.md)中的密码处理说明。

## 3. 为工作室成员建立账号

管理员首次登录后应先完成账号和权限配置：

1. 进入“系统管理 → 用户管理”，为每位成员新建独立账号。
2. 填写姓名、登录名、手机号、所属部门和状态，设置仅本人知晓的临时密码。
3. 通过“更多 → 分配角色”选择合适角色。
4. 要求成员首次登录后立即在“个人中心 → 密码设置”修改密码。
5. 使用普通成员账号重新登录，确认只能看到工作所需菜单和患者范围。

内置角色建议：

| 角色 | 建议使用人 | 权限边界 |
| --- | --- | --- |
| 康复治疗师 | 执行评估、制定计划和处理风险的治疗师 | 康复业务操作；按实际分配查看患者 |
| 文员 | 建档、资料维护和代录打卡人员 | 以查看、资料维护和代录为主，不承担临床复核或审批 |
| 超级管理员 | 工作室明确负责人 | 系统、用户、角色和全部业务管理；不得作为日常共用账号 |

在“系统管理 → 角色管理”调整权限时遵循最小权限原则。不要随意修改内置菜单、删除默认角色
或给所有成员授予超级管理员权限。成员离职或停止合作当天应停用其账号并完成患者转交。

## 4. 后台菜单说明

日常业务集中在左侧“康复管理”菜单：

| 菜单 | 用途 |
| --- | --- |
| 康复工作台 | 查看我的患者、待复评、高风险、低依从性和近期概览 |
| 患者管理 | 新建档案、分配治疗师、查看患者完整业务时间线 |
| 评估管理 | 新建和维护各类评估，生成报告 |
| 报告中心 | 复核、审批、预览、导出、锁版和查看版本 |
| 训练计划中心 | 创建计划、维护任务、查看执行和进度 |
| 打卡记录 | 查看训练记录或由治疗师、文员代录 |
| 复评触发 | 处理到期、疼痛升级、低依从性和阶段结束等复评条件 |
| 通知中心 | 查看和处理系统生成的业务通知 |
| 风险提醒中心 | 确认、解决或忽略有依据的风险提醒 |
| 机构运营看板 | 管理员查看机构整体业务概览 |
| 审计日志 | 查询康复业务的重要操作记录 |

不同账号看到的菜单和按钮会因角色权限、患者归属而不同。缺少菜单时不要反复重建数据，先让
管理员核对用户状态、角色、菜单权限和患者治疗师分配，再退出并重新登录。

## 5. 标准业务流程

推荐始终从“患者管理”进入同一患者详情页完成工作，以避免把评估、报告或计划关联到错误的
患者或康复周期。

### 5.1 新建患者和康复周期

1. 进入“康复管理 → 患者管理”，点击“新增”。
2. 填写姓名、手机号、性别、年龄、主诉、疼痛部位、疼痛评分、来源渠道和备注。
3. 新建患者时保留“初始化 Episode”开启，选择 Episode 类型并填写本阶段主要目标。
4. 保存后打开“详情”，确认患者编号、当前 Episode、当前阶段和主责治疗师。
5. 点击“分配”，将患者分配给实际负责的康复治疗师；需要换人时使用“转交”并记录原因。

Episode 代表一次完整康复周期。不要为了同一次康复反复新建患者；复评和计划应继续关联到
正确的患者及 Episode。

### 5.2 完成初评或专项评估

1. 在患者详情的“评估记录”页签点击“新建评估”。也可从“评估管理 → 新建评估”进入。
2. 再次核对患者、Episode、评估日期和评估类型。
3. 填写本次重点、疼痛评分、红旗备注以及对应评估表单。系统当前支持静态评估、身体成分、
   NASM-CES、SFMA、FMS、YBT、OpenCap、观察和综合评估等类型。
4. 尚未完成时点击“保存草稿”；完成当前内容后使用“保存并继续”或“保存并返回”。
5. 打开评估详情，核对数据状态、质量等级、置信等级、异常项、红旗和总结。

发现红旗、显著疼痛加重或数据不完整时，应先按工作室安全流程人工处理，不要仅依赖系统自动
结论。删除和归档是不同操作；有效业务记录优先归档，不要为“整理页面”直接删除。

### 5.3 生成、复核和导出报告

1. 在评估列表或评估详情点击“生成报告”。
2. 进入“报告中心”，按患者姓名或患者编号找到报告。
3. 点击“预览”，人工核对患者、评估编号、结论、风险、建议和版本。
4. 按权限依次执行“复核 → 审批”。完成后可“锁版”，避免已确认内容被意外修改。
5. 根据需要导出 DOCX 或 PDF，并将文件保存到工作室批准的受控位置。

报告导出文件包含患者信息。不得上传到公开 GitHub Issue、普通群聊、公共网盘或个人未经授权
的云盘。需要修改已锁定报告时，由有权限的管理员说明原因后解锁，重新复核并保留版本记录。

### 5.4 制定训练计划和任务

1. 从患者详情“评估记录”点击“创建计划”，或在“计划记录”点击“新建计划”。
2. 核对患者、Episode、来源评估和主责治疗师。
3. 填写计划名称、类型、起始日期、周期、复评周期、强度、目标、禁忌和注意事项。
4. 目标字段标注为 JSON 时必须输入合法 JSON，例如
   `[{"goal":"疼痛控制至 NRS 不高于 2"}]`；不确定时先保存草稿并由技术负责人核对。
5. 保存后进入计划详情，在“任务列表”新增任务，填写任务名称、模块、执行类型、组数、次数、
   保持时间、周频次和剂量说明。
6. 检查任务顺序和内容后激活计划。执行中的计划可暂停，疗程完成后再标记“完成”。

禁忌、注意事项和剂量必须由具备相应职责的人员人工确认。不要为了快速下发而省略这些字段。

### 5.5 记录训练执行和进度

1. 在计划详情的“打卡记录”点击“新增代录打卡”，或进入“打卡记录”菜单点击“新增”。
2. 选择正确患者、Episode 和计划，填写打卡日期、整体完成率、训练前后疼痛、疲劳、信心和
   备注。
3. 对每个任务记录完成、部分完成、跳过或因疼痛停止，并填写实际组数、次数和症状。
4. 保存后查看“执行明细”。在计划详情“进度追踪”查看完成率、依从性和疼痛趋势；需要时由
   有权限人员点击“重算进度”。

如果患者因疼痛停止、疼痛持续上升或出现异常症状，应如实记录并进入风险处理流程，不要把
状态改成“已完成”来提高完成率。

### 5.6 处理风险、随访和复评

1. 每日查看“康复工作台”和“风险提醒中心”。
2. 对提醒先核对患者详情、评估、计划和打卡原始记录，再执行“确认”。
3. 处理完成且有依据时标记“解决”；只有确认属于误报或不适用时才“忽略”，并记录原因。
4. 在“复评触发”处理待办。对需要复测的记录点击“转复评”，再建立与原 Episode 关联的复评。
5. 使用与初评可比较的评估类型和测量条件完成复评，生成新报告并对照前后变化。
6. 根据复评结果调整计划、继续当前阶段、暂停/转诊，或完成本次康复周期。

系统可因时间到期、疼痛升级、低依从性、阶段结束、目标未达成或目标已达成触发复评。系统
提醒是工作队列，不替代治疗师的人工判断。

## 6. 管理员日常工作

### 每日

- 确认 Docker、MySQL、Redis、后端和管理端健康。
- 查看高风险、待复评、低依从性和最近错误。
- 确认离开岗位的成员已退出账号，不在公共设备保存密码。

### 每周

- 检查未处理风险、长时间草稿、异常打卡和未分配患者。
- 核对成员账号、角色和患者归属是否仍然正确。
- 使用启动器“创建备份”，并确认备份时间和文件存在。

### 更新或维护前

1. 创建并核实数据库与附件加密备份。
2. 记录当前版本、患者数量、最近评估和最近报告。
3. 更新后检查登录、菜单权限、患者数量、附件、评估、报告和迁移账本。

正常启动、停止、重启、更新和卸载不得执行 `docker compose down -v`。备份包含患者数据，
备份文件和解密口令必须分开保存。详细流程见[备份与迁移说明](desktop-backup-migration.md)。

## 7. 常见问题

### 点击“打开系统”没有反应或页面打不开

回到启动器检查 Docker、MySQL、Redis、后端和管理端状态。先确认 Docker Desktop 已运行，
再点击“重启服务”。仍失败时点击“查看日志”并复制脱敏诊断信息给技术负责人；不要发送原始
数据库、患者附件、密码或 Token。

### 可以登录但看不到“康复管理”或某个按钮

由管理员检查“系统管理 → 用户管理”中的账号状态和分配角色，再检查患者是否已分配给该治疗
师。修改权限后退出并重新登录，使菜单重新加载。

### 手机或平板打不开 `127.0.0.1`

`127.0.0.1` 永远指当前设备自身。移动设备必须使用局域网部署设备的实际私网 IP，并先安装
局域网 CA；桌面版默认本机模式不能直接供手机访问。

### 登录后看不到原有患者

先确认登录租户仍为“工作室内部”，再检查账号、角色和患者归属。不要重新运行初始化、创建
同名患者或删除 Docker 数据卷来“找回”数据。

### 端口被占用

桌面版在启动器中修改端口后重新启动服务，并始终使用启动器显示的新地址。局域网版应先由
管理员检查冲突和防火墙规则，不要直接暴露 MySQL、Redis 或 Java 后端端口。

## 8. 下班前检查

- 已保存当天患者、评估、计划、打卡、随访和风险处理记录。
- 没有把报告、截图、备份或患者信息留在公共下载目录或聊天软件。
- 共用设备已退出账号；管理员账号没有交给其他成员日常使用。
- 当天高风险和待复评事项已有负责人和处理记录。
- 需要关机时先正常停止服务；不删除数据卷和用户数据目录。
