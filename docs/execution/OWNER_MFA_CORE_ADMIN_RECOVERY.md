# Core 内置管理员密码恢复：Owner MFA 受控流程

## 状态与适用边界

此功能是**独立恢复通道**，不是普通账号修改接口，也不是取消 Core 登录。默认关闭，必须由正式软件所有者在受控维护窗口启用。它只能恢复本机独立工作室**租户 ID 1 / 用户 ID 1 / `admin`** 的密码，要求该记录仍是启用中的 `super_admin`；不会新建账户、修改用户名、签发许可证、赋予新权限或接触患者资料。

此版本的协议和界面已经通过合成 Owner MFA HTTP、桌面 Rust 及前端单元测试；**正式已安装软件/Owner 服务未部署本次改动，真实 `admin` 密码尚未恢复**。仅测试代码通过不能替代正式发布审批。

## 经过人工审批后的操作顺序

1. 对正式 Core 和独立 Owner 数据做可验证的加密备份，确认 Owner/TOTP 管理员身份、设备控制权、发行版本与已签名安装程序。不得利用临时关闭身份认证或修改数据库哈希来跳过身份确认。
2. 签发、验证并分别更新 Owner 服务和桌面启动器安装包。Owner 必须继续使用严格 HTTPS 且仅监听本机；发行版本来源及 SHA-256 应记录。**不允许只替换某个网页或复制文件冒充正式部署**。
3. 仅在现场维护窗口为 Owner 服务配置 `REHAB_CORE_ADMIN_RECOVERY_ENABLED=true`，其余时间保持未配置/`false`；从本机打开 `https://127.0.0.1:9444/owner/console`，用独立 Owner 密码和 TOTP 正常登录。
4. 在桌面启动器点“通过 Owner MFA 找回管理员密码”，获得只存在于启动器内存的 43 位设备挑战码（有效10分钟）。复制到 Owner 控制台的恢复表单，输入最新 TOTP 完成高风险操作二次确认；每小时最多签发3次。
5. Owner 签发仅可用于恢复 Core `admin` 密码的一次性随机授权码。它有效120秒，在 Owner SQLite 仅保存 SHA-256；浏览器刷新、退出登录时不保留授权码。将授权码粘贴到**刚生成挑战码的同一个启动器实例**，在启动器本地输入并确认12–16位新密码。**新密码不传到 Owner、聊天、日志或源码**。
6. 启动器检查 Docker 服务健康→严格 TLS 校验并原子消耗 Owner 授权→完成加密 SQL/附件备份→只更新 `admin` 的 bcrypt 密码→撤销 DB 中该用户旧 OAuth2 access/refresh tokens→清理 Redis **OAuth2 access-token 名空间**。先验证授权再做备份，避免无授权用户反复触发大量备份；**但备份失败也会消耗该授权码**，需重新申请。缓存清理可能令其他已登录用户重新登录，但不会删除临床/系统缓存。操作失败时恢复前应先核对数据库状态及上一步日志。
7. 在正常 Core 登录页 `https://127.0.0.1:18443/login` 使用租户“工作室内部”、`admin` 和新密码完成真正的账号登录；核对 Owner 链式审计 `CORE_ADMIN_RECOVERY_AUTHORIZED` / `CORE_ADMIN_RECOVERY_REDEEMED` 与加密备份文件存在，并测试旧会话失效。
8. 关闭 Owner 的恢复开关并验证两条恢复 API 重新返回404；保留审计证据和私有加密备份。不得将新密码或 Owner MFA 凭据写入普通 Markdown、Excel、Git 或咨询对话。

## 安全设计与拒绝条件

- 缺失 Owner MFA 会话或 TOTP 再验证、错误挑战、未经授权的 Origin、非 loopback、重复使用、授权到期、过于频繁：全部拒绝。
- Owner 本身并不接触 Core 管理员的新密码；授权严格绑定桌面生成的随机挑战，回执限制 `tenantId=1,userId=1,username=admin,scope=password-only`。
- 现有启动器 `update_admin_credentials` 在 `license-required` 正式授权版中**继续保持禁用**；新的 `recover_admin_credentials` 是独立流程。
- 任何服务不健康、加密备份失败或恢复授权校验失败：不得更新真实密码。
- 数据库只允许更新现存的指定管理员，必须仍具备现有超级管理员角色；不可新建或提升其他用户。
- 既有管理员 OAuth2 数据库令牌失效，Redis OAuth2 token 命名空间失效；正式数据库、Owner 的任何备份恢复与最小权限必须由人工审核。

## 测试范围与未覆盖项

- Owner HTTP/服务端四组恢复用例，另有旧版 Owner 测试全部回归通过。
- 桌面 Rust：随机挑战格式、授权身份限定、原密码不出现在 SQL、角色/租户限定。
- 新增 Redis 缓存范围测试：独立 `network:none` Redis 7.4 容器，两个合成 OAuth2 Token 删除、非授权临床与配置缓存保留。
- 真实 Core 036 加密备份进入一次性 MySQL 验证的进一步写入型测试**被安全检查阻止，尚未执行**；不得以单元测试代替这项验证。
- 未进行真实 Owner MFA 的本机发布、Core `admin` 真密码恢复或正式浏览器登录验收。

## 交付判断

开发和离线测试成功 ≠ 已通过正式发行签名 ≠ 已部署 Owner/启动器 ≠ 已完成真实管理员登录。只有设备管理员审批、签名安装、完整回归和真实登录通过后，才能将账号恢复任务标记为完成。
