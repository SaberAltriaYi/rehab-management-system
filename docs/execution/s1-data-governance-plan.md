# S1-03 合成数据治理实施边界

2026-10-27，执行前方案。仅开发、隔离验收，不在现用业务库标记或归档任何记录。

1. 追加迁移 035，为患者增加 `data_origin`，已有记录默认 `REAL`；不改原有列/临床记录、历史校验和或自动识别姓名。状态为 REAL（业务默认分类）、SYNTHETIC（已确认虚构）、SYNTHETIC_ARCHIVED（虚构资料逻辑归档）。REAL 表示业务统计默认纳入，不表示软件已核验其医学真实性。
2. 新增独立治理接口，仅机构管理员/超级管理员且拥有新专属权限者可用；迁移只登记权限，不自动授予任何已有角色。要求准确患者编号二次确认、预期原状态及理由。允许 REAL→SYNTHETIC→SYNTHETIC_ARCHIVED→SYNTHETIC，禁止模拟转回真实；行锁及同事务审计，失败回滚。归档不删除数据、不改治疗阶段、不注销其他账号。
3. 普通建档/导入默认 REAL，普通更新不能设置来源；列表/详情/导出显示来源，默认不列已归档模拟记录，提供明确筛选及恢复入口。统计仅纳入 REAL，且继续机构/角色/部门权限过滤；实际工作项和未读通知不以统计排除名义丢失。
4. 桌面与移动员工概览、机构经营/工作量/风险统计统一过滤；原有临床待办仍可追溯。模拟报告必须显示“模拟数据/非临床用途”；旧报告的来源回填、独立 HEP/运动同步标签列为后续跨系统契约验收，不能声称本批完成整个临床闭环。
5. 先以合成 H2/MySQL 验证权限/机构/确认/并发/审计回滚/统计/归档恢复，再运行完整后端、前端构建与既有迁移/打包检查。追加迁移需在空库与升级副本验证；现用环境升级仍须新备份、容量检查和副本演练。
