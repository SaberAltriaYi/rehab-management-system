# S1-04 评估摘要异常与JSON解析隐私

2026-10-27。只修现有静态、NASM-CES、SFMA摘要/协议入口的异常诊断，不新增临床功能、不启用AI、不改变正常评分/分解规则，不改患者表或迁移。不升级现用后端/库。

## 实际风险及修补

- `RehabAssessmentServiceImpl.buildAndSerializeModuleData` 三组主摘要/保守降级异常日志曾带原异常文字和堆栈；原异常文字也传给降级摘要，可能夹带输入内容。改为固定模块/错误类别，降级原因统一为“自动摘要未完成，请人工复核”，不带参数、原异常、cause或堆栈。主摘要失败仍走原保守降级；再次失败仍保留原payload，不删除原件。
- 进一步检查发现三个Builder及SFMA原书协议调用通用 `JsonUtils.parseObject`，该工具会在抛异常前打印原JSON和Jackson异常。新增包内 `RehabAssessmentJson`，沿用相同ObjectMapper/TypeReference直接解析，失败只抛固定、无cause的格式错误，不改通用上游工具、mapper配置或其他领域。
- 静态/NASM原有非法字符串转空对象的语义保持；SFMA/协议仍严格拒绝不合法JSON，格式错误现在可按已有SFMA参数错误正常处理，不把解析失败当作有效评估。合法数字0、负数和原备注保持。**此批不宣称所有来源输入已保真**：静态/NASM旧空对象降级需要后续显式输入校验/恢复治理，见下一项计划。
