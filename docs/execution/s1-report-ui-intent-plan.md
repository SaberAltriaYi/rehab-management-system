# S1-04 下一项：报告UI请求意图与恢复

2026-10-27，方案记录，尚未实施，不算功能验收。依赖036及服务端幂等契约，先完成传输隐私补丁CI。沿用原分支，现用业务不升级，AI关闭。

## 采用的边界

- 三个入口统一使用同一生成逻辑：评估列表、评估详情、患者详情。确认框出现前就锁定该评估的UI忙状态，防止双击排队出现多个确认框。重复在途请求合并为同一Promise；成功后下一次明确操作才生成新UUID。
- 同一次意图因超时/连接失败而结果不明，保留原UUID，重试确认原结果，不自动换号。请求参数改变或用户想基于新评估创建新修订时，必须先提示核对报告中心，再明确新意图；不悄悄把旧UUID用于不同参数，不删除旧报告。
- 使用安全随机UUID，不用Math.random；缓存有上限且不能靠静默淘汰未确认请求释放空间。只在本机内存保留必要状态，不新增临床正文/令牌持久化。页面刷新丢失意图的场景必须明示先核对报告中心，不能声称跨刷新自动去重已完成。
- 登录、退出、用户/机构/访问机构变更时清理状态并递增客户端epoch；旧在途响应只允许完成原已授权请求，不得把旧报告ID/提示渲染到新身份界面，也不能清掉新身份的等待状态。挂到user store resetState及相关auth上下文变化；执行器保持纯模块，不引入API/store循环依赖，不读取或输出凭据。

## 先协商服务端契约

不能仅凭新前端发送requestKey，就宣称旧后端会去重。建议追加受原“生成报告”权限保护的只读契约探测接口：只返回协议版本/是否就绪，不返回患者、密钥、许可证正文或数据库细节；就绪需匹配036固定迁移账本及实际请求表，不用临时建表代替迁移。

新后端就绪才启用自动编号。旧后端404可作为已知不支持，但403/401、网络失败和500不能被降级成“安全重试已可用”。旧版兼容路径需明确提示不能保证重试去重、先核对原报告；不能悄悄吞错后重发。可选探测只抑制已知404提示，不能全局静默认证/服务错误。

## 测试和剩余关联项

轻量纯模块测试：双击/单飞、未知结果复用编号、成功后新编号、参数冲突、上限、身份切换和迟到响应、随机源失效、旧后端/无权限/失败探测分开处理。三个Vue入口均使用统一逻辑；新服务端契约权限与账本缺失/漂移/就绪分别测。低容量时本机重型构建NOT_RUN，完整构建/类型和后端回归继续走既有CI，不减少测试。

检查Axios刷新恢复的独立边界：当前刷新请求未显式设置超时；原队列在刷新失败时重放旧请求，可能让等待者再次进入队列。后续需有独立的单次刷新/全部等待者成功或失败收敛、超时及身份变化测试，再做最小修补，不能以改变认证规则或吞掉401代替。当前传输隐私补丁没有声称这些恢复缺口已解决。
