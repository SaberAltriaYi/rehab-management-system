# S1-04 报告 UI 请求意图与恢复：验证记录

日期：2026-10-27。代码、隔离测试、现用环境、发布验收分别记录。此批不升级业务环境、不创建业务账号、不改权限、不启用AI；沿用 `feature/reporter-engine-assessment-20261013`，不合并master、不发布安装器。

## 原因与影响范围

后端036已有请求去重，但三个页面仍直接POST，没有稳定请求编号；双击、超时后重试可能创建重复草稿。只给前端加UUID也无法证明旧后台真的支持去重。

- 评估列表、评估详情、患者详情统一使用 `useReportGeneration`。确认之前进入忙态，内存执行器按评估合并在途操作；成功才结束该意图，后续明确操作用新安全随机UUID。
- 发送后失败只提示“结果尚未确认”，原编号保留；同一意图重试不换号，不接受悄悄改变参数。上限64，不自动淘汰未知结果。显式“核对后重置”先二次确认，提醒先核对报告中心、原报告不删除且新操作可能新增修订。刷新页面无法恢复编号，确认文案明确说明这一限制。
- 意图不写浏览器存储、日志或诊断；只保留必要参数、编号和状态于内存。正常登录、退出、用户store重置、机构/访问机构变化清理并增加epoch；令牌正常刷新不等于换身份，不清掉该意图。迟到响应不能显示到新身份或卸载后的组件，也不能清理新身份在途状态。
- 新增受原 `rehab:assessment:generate-report` 权限保护的 GET `/rehab/report/generation-contract`，仅返回协议版本和ready。检查036固定校验和、InnoDB、机构/评估/操作人/编号摘要主键顺序及必要结果列；只读元数据/空结果，不查询患者，不建表，不补账本，不暴露底层错误。缺失或漂移返回未就绪。
- 只有新契约明确ready才带编号。只有真正HTTP404可进入明确确认的旧后台模式（不发送假去重编号）；401/403/500/网络错误不能冒充旧后台。可选探测只静默特定GET的404通知，其他错误沿用原处理。已有v1未知结果不允许降级旧模式重发。
- 不改临床表、旧迁移校验和、原报告/快照/审批规则、认证和租户隔离。不改变原正常生成接口的可选编号兼容。
