# S1-04 下一项：登录刷新恢复（待实施）

2026-10-27，仅基于当前管理端 `src/config/axios/service.ts` 和 `utils/auth.ts` 的代码审计；不是已经修复或现用身份验收。接续先核对报告UI候选及新增Vue effect-scope测试的CI，再实施。本机容量低于8GiB时只跑轻量测试，完整构建交CI。

## 已发现的边界

1. 原 `requestList` 只存resolve回放函数。刷新失败时仍回放等待请求，而当前请求转登录；等待者可能再次401进队列，被finally清空后永远不settle。
2. 无刷新令牌的提前返回发生在try/finally外，`isRefreshToken`可能永久true，后续请求持续等待。
3. 刷新通过全局axios直接POST，尚未显式超时；不能用普通service的30秒配置假定它也有30秒上限。
4. 没有每个原请求的“已重放一次”标记，刷新成功但继续401可能递归刷新。请求加密已有isEncrypted标记，改队列时需保留，不可重复加密请求正文。
5. 刷新进行中若退出/重登/更换机构，旧刷新成功可写回旧凭据，旧请求可能携带新身份重放。仅在报告意图层过滤迟到结果，不等于修好整个认证层。不得输出/持久化新日志凭据，也不得为了测试读取现用token。

## 最小修补方案

- 保留现有认证接口、租户校验、URL编码刷新正文和单次租户头，不改后端token规则。提取可注入的单飞刷新执行器，一次刷新Promise由全部等待者共享；成功全部继续，失败全部reject，不在失败分支回放旧请求。
- 显式有限超时与AbortSignal；定时器回收，等待者必有终态；失败使用固定去敏错误，不保留Axios原始config/body/cause。失败身份在正常重新登录前不自动发起刷新风暴。
- 独立认证epoch覆盖正常登录/退出/机构变化，正常刷新不递增。每个请求在首次发送时捕获epoch和机构上下文；重放和接收旧响应前核对，旧身份不得写回凭据/重放临床请求或触发新身份退出弹窗。需要对正常登录、刷新、匿名登录/验证码和用户缓存路径逐项回归，不把报告模块自身的epoch直接冒充全局认证协议。
- 每个请求最多一次认证重放；并发晚到401若其原token已被同一身份刷新，可用当前token重放一次而不再刷新。继续401终止并按原正常登录处理，绝不绕过认证。原加密标志、下载、上传、取消、可选404探测继续兼容。
- 登录页/重复退出通知也必须返回拒绝终态，不能靠弹窗返回undefined当成功；上下文变化静默丢弃旧结果，真正当前身份失败继续正常登录提示。

## 必须先写的合成测试

并发401只刷新一次；缺刷新令牌不会留下忙态；HTTP/业务刷新失败使全部等待者失败且无原请求重放；超时和abort；刷新成功仍401最多一次重放；刷新后晚到旧401不再次刷新；退出/同账号重登/跨机构/访问机构变化立即终止旧等待者、阻止旧凭据覆盖；迟到成功/失败不清新身份状态；错误无凭据/临床正文；普通登录和加密/下载/上传保持。需用实际Axios拦截链和回环/可注入adapter测试，不仅做纯模块和源码字符串检查。
