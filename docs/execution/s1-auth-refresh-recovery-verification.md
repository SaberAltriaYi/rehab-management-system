# S1-04 登录刷新恢复验证

2026-10-27，沿用 `feature/reporter-engine-assessment-20261013`。AI关闭，不读取真实凭据，不创建现用账号，不扩大权限，不绕过正常登录/验证码/审批。此批仅更改管理端认证恢复，不改后端认证协议、数据库、业务表或迁移账本。

## 问题、原因和影响

旧队列只有resolve回放函数；无刷新令牌的提前返回不清理刷新状态；失败仍回放原请求；直接Axios刷新无显式超时；刷新成功后持续401可能递归；退出/重登或换机构时旧刷新结果没有身份边界。前批报告请求意图只能保护该报告UI，不能替代整个认证链路的修复。

已实现：

- 单飞刷新Promise供所有等待者共享，成功才能重放，失败全部拒绝。不再保留原回调队列，不在失败后重发临床正文。缺刷新凭据也有确定终态。
- 刷新HTTP和共享执行器均设30秒上限，AbortSignal终止过期刷新；单个请求取消不取消其他等待者的刷新。失败的当前身份阻止刷新风暴，正常重新登录/身份重置后方可恢复。
- 每个请求最多一次认证重放；已被同一身份刷新过的旧token迟到401仅尝试一次当前token，不再发起第二次刷新；重放仍401则终止。保留原加密重放标志，避免重复加密，保留上传/下载/表单和可选404探测语义。
- 新增独立认证epoch，不含token。登录、退出、机构、访问机构、user store重置时清理认证等待者和报告意图。正常同页刷新不变更epoch。每个请求首次发送捕获上下文，旧成功/错误响应不能进入新身份页面；旧刷新不能覆盖新凭据，旧登录提示的迟到确认不能清空新身份。
- 其他标签页的认证相关storage键变化也保守取消旧工作，只检查键，不读取事件值、不新增持久化或日志。跨标签页正常令牌轮换也可能取消当前请求，需要重新操作；不声称多窗口无感协同已完整实现。
- 原登录白名单/isToken=false不再误附当前Bearer或访问机构头，也不获得认证自动重放。机构头继续来自当前上下文，Owner继续使用既有固定机构；服务端认证/租户验证不变。原HTTP错误仍严格拒绝，不把HTTP401改为成功。
- 登录页或已有登录提示也返回拒绝终态，不返回undefined伪成功。恢复错误仅固定类别/文字，不保存原Axios配置、患者正文、令牌、cause。原有凭据缓存机制未在此批全面替换，不能说已完成所有存储风险整改。
