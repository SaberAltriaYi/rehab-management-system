# D4-A：套餐 113 功能目录与机构角色权限分离

日期：2026-11-15
范围：仅源码修改、前端入口和隔离测试。用户明确禁止激活计划 2、套餐 113、Owner/Core 机器通道或创建任何机构账号；本次严格遵守。

## 1. 设计结论

**套餐菜单是机构可订购功能的上限，不是新建机构管理员的默认权限清单。** 机构开户会创建三种不可由机构用户编辑/删除的系统角色模板；初始管理员用户只绑定 `tenant_admin`。套餐变更时，三种模板重新按各自 allowlist 与套餐菜单交集计算；其他自定义角色仍被限制在套餐菜单范围内。

| 角色编码 | 名称 | 数据范围 | 授权职责 |
|---|---|---|---|
| `tenant_admin` | 机构管理员 | `ALL`（仅当前租户） | 员工账号、患者建档/档案/分配、就诊阶段与分配管理、机构运营、临床报告只读、动作评估只读 |
| `tenant_rehab_therapist` | 康复治疗师 | `SELF` + 既有患者归属/治疗师分配过滤 | 被分配患者、评估录入、报告生成、康复计划/任务、打卡/进度/复评、动作采集/上传/处理 |
| `tenant_rehab_clinical_reviewer` | 临床审核人 | `ALL`（必须存在当前租户上下文） | 当前机构内患者/评估只读、报告复核/审批/锁定、动作评估复核/签署/审计 |

**三个角色的实际菜单数**（使用 2026-11-15 对套餐 113 的 274 项菜单快照，含完整上级导航）：

| 角色 | 精确权限串 | 获得菜单 ID | 菜单组成（目录/页面/按钮） |
|---|---:|---:|---:|
| 机构管理员 | 30 | **35** | 2 / 10 / 23 |
| 康复治疗师 | 44 | **46** | 1 / 10 / 35 |
| 临床审核人 | 16 | **18** | 1 / 5 / 12 |

64 个角色权限串均能在套餐 113 当前菜单目录中匹配；**没有**权限串依赖不存在的菜单记录。274 项目录中共有 218 项带权限串；未授予任何默认角色的目录权限串为 154 项。上表的菜单数大于权限串数，是因为完整父级目录/页面也会加入，以确保导航树可用。

## 2. 高风险权限边界

以下权限不进入任何默认机构角色：

- 平台/租户/套餐管理：`system:tenant:*`、`system:tenant-package:*`。
- 角色/权限结构控制：`system:role:*`、`system:permission:assign-role-menu`、`system:permission:assign-user-role`、`system:permission:assign-role-data-scope`。
- 基础设施控制：`infra:*`，包括系统配置、数据源配置、任务触发。
- 机构用户危险操作：用户删除、导入/导出、密码重置、任意角色分配。
- 临床数据危险操作：患者删除/导出、CRM 绑定、`rehab:patient:data-governance`、报告解锁、报告/动作评估导出。

具体职责边界：

- **机构管理员**：可以创建/更新员工账号，但没有通用 RBAC 角色分配权限；可以分配患者、查看报告和动作结果，但不能复核、审批或签署临床结论。
- **康复治疗师**：患者创建和分配由机构管理员负责；治疗师只能查看/更新自己负责或被分配的患者。治疗师可创建评估、计划、动作采集及处理，但不拥有报告审批、动作复核或签署权限。
- **临床审核人**：可在本机构范围内审核报告、审批/锁定报告、复核和签署动作评估；没有患者建档、评估录入、计划管理、动作采集/处理、报告解锁和系统管理权限。

套餐 113 中的动作工作区菜单 `9718 / rehab:motion:workspace` 的父菜单 ID 为 `2397`，但 `2397` 不在套餐 113 的 274 项菜单中。模板解析器要求父级路径完整，因此**不会将这个孤立菜单授予任何角色**。需在后续菜单目录治理中修复其父级关系，不能通过忽略父级约束来绕过。

## 3. 源码实现

### 3.1 功能目录与角色 allowlist

- 新增 `TenantRolePermissionTemplate`：集中定义三种角色的精确权限串、名称、排序和数据范围。
- 解析菜单时必须同时满足：权限串在角色 allowlist 内、菜单 ID 在当前套餐内、菜单本身启用、所有父级菜单均在套餐内且启用。未知角色、缺失父级、禁用菜单均 fail-closed。
- 机构管理员只获得 30 项明确权限，不再直接得到套餐 113 的全部 274 项菜单。

### 3.2 机构创建与套餐变更

- `TenantServiceImpl.createTenant` 创建机构管理员、康复治疗师、临床审核人三个 `SYSTEM` 角色。
- 首次创建的管理员用户只分配 `tenant_admin`；治疗师/审核人模板创建后不自动绑定任何用户。
- 既有机构在套餐菜单或套餐启用状态发生变更时，会补齐缺失的治疗师/审核人模板，并按新套餐重新计算角色权限；不会自动给任何员工分配新角色。套餐从停用转为启用时也会重算，避免既有机构绕过模板初始化。
- 既有 `tenant_admin` 模板缺失、模板角色类型/状态异常或重复时，操作直接失败，不会静默重建管理员身份。
- 自定义角色继续执行 `当前角色菜单 ∩ 当前套餐菜单`，不能超出订阅功能范围。

### 3.3 数据范围

- `tenant_admin` 与临床审核人的 `ALL` 仅在当前租户上下文内有效；租户隔离仍由现有 MyBatis TenantLine/租户上下文承担。
- 治疗师角色设置 `SELF`，并继续使用 `RehabDataPermissionService` 已有的患者归属和治疗师分配过滤。
- 临床审核人没有当前租户上下文或上下文被忽略时，患者可见集合返回空集，不会以 `null` 代表无限可见。
- 新增内部 `updateTenantTemplateRoleDataScope`，只允许更新三个指定的启用 `SYSTEM` 模板角色，且数据范围必须与角色定义完全一致；治疗师不能被设置为 `ALL`。

### 3.4 临床审核权限

- 增加 `tenant_rehab_clinical_reviewer` 角色代码；新治疗师模板采用独立编码 `tenant_rehab_therapist`，保留历史 `rehab_therapist` 识别但不将其作为新模板。
- 报告审批/锁定、动作复核/签署和模块审计服务识别临床审核人；报告解锁仍保留系统拥有者权限。
- 动作原始人工输入接口从 `rehab:motion:review` 调整为 `rehab:motion:create`，避免审核人借助 review 权限修改原始人工输入；治疗师拥有 create 权限，可完成录入。

### 3.5 员工岗位分配

- 新增 `POST /system/user/assign-rehab-staff-role`，受 `system:user:update` 权限保护，服务端再次要求操作者是当前租户的 `tenant_admin`。
- 机构管理员**仅可分配康复治疗师**；不能分配 `tenant_admin`、`super_admin`、自定义角色或临床审核人。
- 服务端拒绝：当前操作者给自己改岗、修改机构联系管理员、跨租户用户、停用用户、目标用户已有非标准/高权限角色、任意未知角色代码。
- 分配时用单角色集合替换已有标准治疗师角色，避免追加角色造成权限叠加；分配动作写入系统操作日志。
- 工作室员工页面增加“岗位”入口，只显示治疗师选项。临床审核人角色的独立资质核验与授权仍需由具备系统级角色分配权限的管理员执行；本轮仅限制机构管理员不得授予，未实现资质核验工作流或专用审批入口。

**临床资质核验目前不是系统自动验证流程。** 当前软件仅限制机构管理员不能自助授予审核人角色，并在通用角色分配界面显示高权限警示；实际执业资质核验必须由系统级管理员在外部完成并留档，再通过受控的系统级角色分配操作授权。本轮没有建设证书上传、专用审批入口或资质有效期复核。不得把该角色当作普通员工岗位。

## 5. 生产隔离边界与已知限制

- 没有新增或执行数据库迁移；没有写入正式角色、用户、机构、套餐、计划或租户授权。
- 套餐 **113 仍停用**、计划 **2 仍停用**；Owner/Core 机器身份开关保持关闭；没有真实机构开户。
- 没有部署、重启正式 Core/Owner 服务，也没有写入 Owner `.env`、机器令牌、HEP 私钥或患者资料。
- 新租户创建时会生成三个角色；既有租户会在下一次套餐菜单或启用状态变更时补齐治疗师/审核人角色。不会自动把任何现有员工变成审核人。
- 员工岗位分配时，会校验现有角色归属本租户及新模板唯一性；角色引用跨租户、重复模板等异常一律拒绝，不会选择第一条继续授权。
- 临床审核人资质验证仍需系统级管理员人工核验/审批，暂未建设证书上传、双人审批或有效期复核工作流。
- 系统级通用 RBAC 仍允许管理员把多个角色组合给同一用户；本轮没有强制禁止“临床审核人 + 治疗师/机构管理员”组合。执行人工授权时必须核查现有角色，是否实施互斥角色约束需下一阶段确认。
- 生产 Core 已有一条历史 `rehab_therapist` 自定义角色（`tenant_id=1`，74 条角色菜单关联）；本次只读发现、未修改。新模板采用 `tenant_rehab_therapist` 独立编码避免冲突。历史账号仍由 Rehab 权限逻辑识别，但旧角色不用于新邀请，也不会自动迁移；需另行审查其权限并制定迁移方案。
- `rehab:motion:workspace` 菜单父级 2397 缺失，当前模板主动排除；菜单树修复需另行审查。
- 当前只完成后端安全接口和管理端“岗位”入口，没有启用正式套餐、计划或机器开户通道。
- 当前阶段完成的是源码、H2 合成机构业务回归和前端构建，**新版本尚未构建部署到正式 Core 并执行实际浏览器端到端开户验收**。此前 58/58 的 C2 HTTP 隔离测试属于旧 P0 三菜单候选，不能代替本阶段新权限模型的 HTTP 验收。

**结论：D4-A 源码与隔离验收完成；正式生产启用仍未授权、未执行。**
