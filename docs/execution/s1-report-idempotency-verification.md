## 实现

- 可选UUID `requestKey`，以机构/评估/实际操作人/编号摘要作为幂等范围。权限检查先于账本查询，持有编号不能绕过原对象权限；客户端不能指定操作人或账本租户。
- 同编号同规范化参数重试，返回首次成功的相同报告ID/编号/版本/降级结果，不再次读取模块、生成报告、写版本快照或审计。参数改变、原报告已删除/被重归属时拒绝，不自动替换。新修订应使用新编号。
- 评估行锁、成功请求账本的锁定当前读、报告生成及账本写入处于同一事务，避免MySQL RR旧快照漏掉刚完成的请求；失败全部回滚，编号不被永久占用。数据库复合主键另挡重复写入。
- 036仅新增请求账本，原报告、旧迁移摘要和权限不改。保存SHA-256编号/参数摘要与生成结果元数据，不保存原始编号、备注或临床正文。参数摘要使用私有、带v1域标记的固定JSON编码器，避免全局Web序列化设置变化使升级后的重试失配；已有固定摘要向量回归。
- 管理端API类型已对齐可选字段，但三个业务按钮尚未自动分配/保留重试编号。旧客户端不传时保持原有每次生成新修订，不能据此声称界面超时重试已完全修复。自动编号/重试状态与错误恢复是下一项；不先改变现用前端业务行为。
