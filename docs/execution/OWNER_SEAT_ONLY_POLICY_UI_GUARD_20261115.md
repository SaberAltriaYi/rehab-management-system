# Owner 续期策略：席位修改误操作防护（2026-11-15）

## 背景和工程原因

旧版界面将「无限员工席位」作为独立勾选项，输入框即使填写数值，`parsePolicy()` 仍按复选框签发 `seatLimit=null`。提交后页面调用 `fillPolicyFromTenant()`，无限席位会把数字输入回填为默认的 `6`，使用户误以为数据未保存而重复提交。已批准租户仍可点击「填入标准策略」把到期时间、安装实例数等字段重置为新申请的默认值；泛化的确认提示没有列出会改变的字段。

## 安全修复

- 勾选无限席位时禁用并说明数字输入框，取消勾选后才能填写定额，不再显示会误导的虚拟 `6`。
- 已批准租户不能再调用「填入标准策略」覆盖已签发合同；待审新机构申请仍可使用该按钮。
- 已批准租户维护区域新增「仅调整员工席位」入口。调用 Owner 现有 `POST /owner/v1/tenants/:uuid/policy` 的完整 MFA 校验链路。该入口读取当前许可证并构造仅修改 `seatLimit` 的有效策略，**保留当前真实到期时间、最大部署实例和全部授权模块**，不引用左侧审批模板中的任何值。
- 提交前比较刚查询的许可证与页面所载入的修订代际/策略，发现并发修改立即失败；先显示准确字段差异，要求用户手动确认。普通续期现在也显示所有变更字段，且不再允许无差异操作重复提交以消耗许可证撤销代际。
- 通过服务端写入后再次查询许可证并对比预期策略，避免 UI 的成功提示掩盖实际席位仍为无限。未通过时明确要求停止重试并查审计。
- 始终沿用 Owner MFA 的 `requireStrongOwner()`、TOTP 再认证、授权审计、旧租约代际失效；不改生产库、绕过 MFA 或更改其他机构。

## 验证与限制

- 通过纯函数测试：席位-only 20、原合同字段保留、非法席位拒绝、多字段差异可见。
- 通过真实 Chrome 的合成 Owner API 测试：无当前选择、无限复选框禁用行为、维护界面禁止标准策略覆盖、一次 seat-only POST 只提交席位差异、回读的有效席位、无差异重复更新阻断。测试网络仅连接独立本地临时模拟服务，不接触真实 Owner 写接口。
- Owner 其余 HTTP、MFA、授权相关测试及 desktop 脚本回归在本轮执行。源文件由现有 Owner HTTPS 静态服务器直接提供，无需服务重启，但**已打开的浏览器标签页仍须刷新**；刷新会丢失仅在内存中的 Owner 会话，需要本人重新登录及 TOTP。
- 该修复不会自动恢复历史上已改动的到期时间/部署实例，也不会自动修改现有许可证。任何真实变更必须经本人在 Owner 控制台重新确认。
- 本轮工作是 UI/安全回归修复，不意味着 Rehab Core 自动开户、SaaS 套餐、HEP 037 或正式临床发行门禁已通过。
