# 桌面版故障排查

## 找不到 Docker

安装 Docker Desktop 后重新打开启动器。macOS 确认 Docker.app 位于 Applications；
Windows 确认使用官方安装并完成首次启动。启动器不会代为安装。

## Docker daemon 未运行

打开 Docker Desktop，等待 Engine Running。若仍失败，先在 Docker Desktop 自带诊断中
修复 daemon；不要删除现有卷。

## Compose v2 不可用

升级 Docker Desktop并确认 `docker compose version` 成功。Windows 不要用旧版
`docker-compose.exe`、Git Bash 或 WSL 脚本替代。

## 首次拉取镜像失败

启动器保留已有容器和卷。检查网络、代理和 Docker 镜像仓库设置后再次点击“启动服务”。
镜像版本均固定，不要手工改成 `latest`。

## 端口冲突

先停止服务，再在“端口设置”选择未占用的 1024–65535 端口。HTTP 与 HTTPS 端口不能相同。
V1.0 只接受 `127.0.0.1`，不接受 `0.0.0.0` 或局域网 IP。

## 健康检查超时

打开“查看日志”。错误会说明失败阶段、简要原因和数据目录。复制诊断信息只包含版本、服务
状态、路径和脱敏错误，不含数据库密码、Redis 密码、Token 或患者记录。不要把原始数据库
和附件发到公共 Issue。

## 浏览器证书警告

确认地址为启动器显示的本机地址。需要长期使用时，将用户数据目录 `config/tls/server.crt`
加入本机受信任证书存储；不要全局关闭 TLS 校验。

## 忘记初始密码

如果尚未点击“我已保存”，启动器会继续显示权限受限文件中的初始密码。已隐藏且未修改密码
时，不要编辑数据库；保留数据卷和备份，联系管理员执行受控密码重置。

## 初始密码超过 16 位，登录提示长度错误

这是 `desktop-v1.0.0-preview.1` 的已知缺陷：管理员密码错误复用了 48 位基础设施密钥生成器。
安装修复版后直接使用启动器仍显示的原 48 位临时密码登录，然后进入“个人中心 → 密码设置”，
将密码改为 4–16 位。不要重装数据库、删除 Docker 卷或手工修改密码哈希。

## 更新或卸载后数据仍在

这是预期安全策略。重新安装后会连接稳定命名卷。只有启动器危险区的精确确认流程才删除数据；
不要把 `docker compose down -v` 当作普通修复命令。

## 整店迁移包导入失败

- “密码错误或文件已损坏”：确认迁移密码通过独立渠道完整传递，不要反复猜测。
- “服务未全部健康”：先修复 MySQL、Redis、后端或管理端，再重新导入。
- “附件包含不安全路径”：停止使用该文件，迁移包可能被篡改；重新从可信总店导出。
- 覆盖过程中失败：启动器会保留导入前自动生成的本机加密备份和日志。不要删除卷或反复覆盖，
  先联系管理员按备份恢复方案处理。

迁移包包含患者数据。不要把迁移包、密码或原始错误日志上传到公开 Issue、普通网盘或群聊。

## 修改管理员账号失败

确认四项服务均健康。账号只能使用 4–30 位字母、数字、点、下划线或连字符，密码必须为
12–16 位；账号若被其他用户占用会拒绝修改。修改成功后旧登录令牌立即失效，请使用新账号
重新登录。启动器不会显示当前密码。
