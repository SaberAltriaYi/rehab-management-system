# 桌面版备份与迁移

“创建备份”只在四个服务全部健康时可用。启动器使用容器内 `mysqldump` 的一致性事务导出
数据库，用 `tar` 导出康复附件，并在主机侧用独立随机口令加密。输出位于用户数据目录的
`backups/`：

- `rehab-<UTC时间>.sql.age`
- `rehab-<UTC时间>-attachments.tar.gz.age`
- `rehab-<UTC时间>.json`

解密口令位于权限受限的 `secrets/backup.passphrase`。复制离机备份时，应把 `.age` 文件和
口令分开保管；备份仍包含患者数据，必须使用受控加密介质。不要把任何备份、口令或恢复日志
提交到 Git。

普通本机备份的恢复仍由管理员在隔离环境执行，因为数据库迁移无法保证自动回滚：

1. 停止业务写入并复制当前数据目录和四个卷的快照；
2. 使用与备份匹配的 age 工具和口令解密；
3. 在同版本临时 Compose 项目中恢复数据库和附件；
4. 核对 `internal_schema_history` 001–019、患者数量、附件和登录；
5. 通过验收后才切换正式卷；失败时保留旧卷和日志。

## 总店到分店一键整店迁移

启动器提供专用 `.rehab-transfer` 加密迁移包，不需要复制安装目录：

1. 总店四项服务全部健康后点击“一键导出整店数据”，设置 12–128 位迁移密码。
2. 迁移包包含完整业务数据库（包括系统用户和权限）及康复附件；不包含数据库/Redis 运行
   密码、TLS 私钥、端口、日志、缓存和已有备份。
3. 分店先安装相同或更高的已验收版本并启动至全部健康。
4. 点击“一键导入整店数据”，选择迁移包，输入密码和确认文字 `覆盖导入全部数据`。
5. 启动器先使用分店自身备份口令自动创建本机加密备份，再停止业务写入、全量替换数据库和
   附件、清理 Redis 缓存并重启健康检查。
6. 导入失败时不会删除自动备份和日志；不得反复导入，应先根据错误和备份制定恢复方案。
7. 导入后核对管理员登录、用户角色、患者数量、评估、报告、附件和迁移账本。

迁移是全量克隆/覆盖，不执行门店间数据合并。迁移包和密码必须分开保管，不得上传 GitHub、
公开网盘或普通群聊。
